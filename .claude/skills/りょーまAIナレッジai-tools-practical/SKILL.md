# AIツール実践活用スキル

## Dify（ディファイ）

### 概要
AIアプリケーション（チャットボット・ワークフロー）を構築できるノーコードプラットフォーム。

### 版の選択
| 種類 | 特徴 | 向いているケース |
|---|---|---|
| **ブラウザ版** | すぐ使える。無料版は制限あり。Pro版 月約8,000〜9,000円 | 個人・小規模利用 |
| **ローカル版** | Docker導入が必要。ほぼ無料。日本の上場企業でも採用 | 企業・本格運用 |

### チャットフロー vs ワークフロー
- **チャットフロー**：会話形式。自分専用のChatGPTを作りたい場合に最適（初心者向け）
- **ワークフロー**：複数LLMの並列処理など複雑な処理が可能（中級以上）

### 基本構成
```
[開始] → [知識検索（ナレッジ紐づけ）] → [LLM] → [回答]
```

### 主な活用例
- **ナレッジベース**：PDF・ドキュメントをアップして独自データで回答するBOT
- **Slack連携**：チャットボットをSlackに埋め込む
- **LINE連携**：LINEプラグインでDifyとLINEを直接連携
- **無料Web検索**：Jina Reader（API不要）でWeb検索を組み込む
- **MCPエージェント**：Zapier経由で外部サービス（Googleカレンダー等）と連携

### Dify × LINE BOT 構築手順

**フェーズ1：Dify側の設定**
1. 「最初から作成」→「チャットフロー」を選択
2. ナレッジ（PDF等）をアップしてインデックス化
3. フロー：開始 → 知識検索 → LLM（モデル・プロンプト設定）→ 回答
4. 「プレビュー」で動作確認

**フェーズ2：LINE連携**
1. LINE Developersでチャンネル作成
2. 「チャンネルシークレット」「チャンネルアクセストークン」を取得
3. Dify「LINEボット拡張」でエンドポイント作成（**半角英数字とハイフンのみ**）
4. DifyのWebフックURLをLINE Developersに貼り付け

**よくあるエラー**
- エンドポイント名に日本語・スペース → 半角英数字に修正
- LINEの連携ループ → 新規作成で再試行、スマホアプリから設定
- 意図しない回答 → ナレッジ充実・モデル変更・プロンプト強化

## n8n

### 概要
ノーコード・ローコードのワークフロー自動化ツール。LINEからの入力 → AI生成 → Threads/X投稿などを自動化できる。

### LINE × Threads 自動投稿ワークフロー

**全体の流れ**
```
LINE入力（テーマを送信）
    ↓
[Webhook] ノード（LINEから受信）
    ↓
[LLM] ノード（投稿文を生成）
    ↓
[HTTP Request] ノード（Threadsに投稿）
    ↓（オプション）
[X (Twitter)] ノード（同時投稿で二刀流）
```

**構築手順**

**STEP1：Webhookの設定**
1. n8nに [Webhook] ノード追加
2. POST に設定し、WebhookURLをコピー
3. LINE DevelopersのWebhook URLに貼り付け

**STEP2：LLMノードの設定**
1. LLMノードを追加し、LINEのテキストデータを紐づけ
2. システムプロンプトで役割と文字数を厳格に指定
   例：「必ず500文字以内で出力すること」

**STEP3：Threads投稿ノードの設定**
1. [HTTP Request] ノード追加
2. Threads APIのアクセストークンを設定
3. LLMが生成したテキストを送信パラメータに紐づける

**エラー対応の鉄則**
> 意味のわからないエラーが出たら**スクリーンショットをChatGPTに投げる**。

- 文字数制限エラー → LLMのシステムプロンプトに「〇〇文字以内」を追記
- 原因不明エラー → AIにスクリーンショットを見せて解決策を聞く

## Cursor

### 概要
AI搭載コードエディター。プログラミング以外にも「高機能メモ帳＋AI」としてコンテンツ制作に活用できる。

### 3つのモード
| モード | 用途 |
|---|---|
| **Ask（アスク）** | チャット形式でAIに質問・相談 |
| **Agent（エージェント）** | 複数タスクを自律実行。ファイルへの直接書き込みが可能 |
| **モデル切替** | Claude / GPT-4 / Geminiを自由に切り替えて比較 |

### SNS投稿自動生成のワークフロー

**ナレッジファイルの準備（.md形式で保存）**
1. Xアルゴリズムの解説ファイル（@Web機能で収集）
2. 実績者の攻略ノウハウをまとめたファイル
3. 自分の発信内容・音声書き起こしファイル

**投稿生成の指示例**
```
「上記3つのファイルを参照して、
バズる可能性の高いX投稿を10個作って」
```

**Cursorの強み**
- ファイルの更新が楽：エディタ上でテキストを直接書き換えるだけ
- モデルを変えても同じナレッジベースを参照できる
- GitHubにプッシュするとマークダウンのプレビューが確認できる

### 商談ナレッジの構築
1. 商談を録音（iPhone/Apple Watch）
2. Google AI Studioで文字起こし
3. Cursorに貼り付けて「この顧客への最適提案を生成して」と指示

## MCP（Model Context Protocol）

### 概要
LLMに外部ツールを接続するための「共通規格」。USB Type-Cのような統一コネクタ。Googleカレンダー・Notion・ファイル操作などをClaude等から自然言語で操作できる。

### 導入手順（Claude Desktop）

**必要なもの**
- Claude Desktopアプリ
- Node.js
- 使いたいMCPサーバーのAPIキー

**設定方法**
1. Claude Desktop →「開発者」→「構成を編集（claude_desktop_config.json）」
2. MCPサーバーのコードとAPIキーをペースト
3. Claudeを完全に閉じて再起動

### 主なユースケース
| ツール | できること |
|---|---|
| **Brave Search** | AIがリアルタイムでWeb検索 |
| **File System** | 「デスクトップにファイルを作って」でローカル操作 |
| **Playwright** | AIがブラウザを操作してデータ取得 |
| **Notion** | 生成した資料をNotionに直接保存 |
| **Google Calendar** | 「今日の予定は？」で予定確認 |
| **Blender** | 自然言語だけで3Dモデリング操作 |

**MCPサーバーの探し方**
- GitHub上に多数公開
- 設定がわからない場合：URLをCursorやClaudeに投げて「これに繋ぎたい」と聞けばOK

**注意点**
> 「ファイルを整理して」等の指示でAIが暴走するリスクあり。必ずGitHub等でバックアップを取った状態で使う。

## GenSpark

### 概要
AIエージェント機能を持つマルチモーダルツール。リサーチ・スライド生成・画像/動画制作・診断アプリ作成まで対応。

### 主な活用法

**1. 市場リサーチ → スライド自動生成**
```
エージェント機能でリサーチ（2週間→数分）
    ↓
スライド自動生成（比率・デザインスタイルを指定）
    ↓
ポッドキャスト化（音声で確認・学習教材に再利用）
```

**2. 動画コンテンツ制作**
```
チャットで画像イメージを壁打ち
    ↓
画像生成エージェントで画像作成
    ↓
「画像から動画へ」機能で動かす
    ↓
Canva等で編集 → Instagramリールに活用
```

**3. 診断アプリ作成（ノーコード）**
- 「〇〇診断アプリを作りたい」と相談
- 質問項目・ロジックをチャットで壁打ちして決定
- WebアプリとしてノーコードでURLが発行される

**クレジット節約のコツ**
> チャット（無料）で構成を詰め切ってから生成（有料）を実行する

## Threads自動投稿（Googleスプレッドシート版）

### 構成
- Googleスプレッドシート（Apps Script内蔵）
- Meta for Developers（Threads API）
- 予約日時を入力 → 自動投稿

### 手順
1. スプレッドシートをコピー
2. Meta for DevelopersでThreads APIアプリを作成
3. 「Threads Content Publish」権限を追加
4. スマホのThreadsアプリ → 設定 → ウェブサイトの許可で承認
5. アクセストークンをスプレッドシートに貼り付け
6. 投稿内容・予約日時を入力 → メニューから「開始」

## ゴールシークプロンプト

曖昧な指示でAIにすれ違いをさせない技法：

**通常の問題**
```
ユーザー：「ブログ記事を書いて」
AI：勝手にゴールを解釈して一方的に書き始める
```

**ゴールシークプロンプト**
```
「以下のタスクを実行する前に、
ゴールと手順が曖昧な部分を変数として扱い、
それを確定させるために私に質問してください。
タスク：ブログ記事を書く」

→ AIが「誰向けですか？」「テーマは？」「文字数は？」
  と質問を投げかけ、対話でゴールを明確化してから着手
```

**活用場面**：ブログ記事・企画書・提案書・旅行プラン・LP作成など、あらゆる曖昧な指示に応用可能。

## Claude Code（m2AIスクール）

### Claude Codeとは

Anthropic製のターミナルベースAIエージェント。ChatGPT等のWebAIとの3つの根本的な違い：
1. **ローカル動作**：自分のPCで動く
2. **ファイル直接操作**：ローカルのファイルを読み・書き・実行できる
3. **行動実行**：提案するだけでなく、ファイル作成・プログラム実行まで行う

**非エンジニア向けの入口**
- プログラミング知識不要。日本語の自然言語で操作可能
- Cursor IDEと組み合わせるのが推奨。ファイルを視覚的に確認・プレビューできる
- 料金：Proプラン（$20/月）が安全な出発点。API課金は高コストになりやすい

**Anthropicの3階層**
| 層 | ツール | 特徴 |
|---|---|---|
| 基本 | Claude Web | ブラウザチャット |
| 中級 | Claude Desktop | ローカル連携可 |
| 上級 | Claude Code | ターミナル＋自律実行 |

## Harness（ハーネス）

### なぜHarnessが生まれたか

デフォルトのClaude Codeが抱える3つの失敗：
1. **報酬ハッキング**：タスクが未完でも「完了した」と宣言してしまう
2. **コンテキスト喪失**：長いセッションでは重要な制約がauto-compactで消える
3. **曖昧解釈**：「テスト」などの言葉が自由解釈され暴走する

### アーキテクチャ

**SSOT（唯一の真実の源）**
- `state.md`：現在の状態を記録するファイル
- Playbook：ステップバイステップの手順
- Claudeはこの2つのファイルの外側で行動してはいけない

**セッションリセット耐性**
タスクをInput → Process → Outputの状態遷移でモデル化し、全てstate.mdに書き込む。セッションが切れても、次のセッションでstate.mdを読めば完全復旧できる。

**スキル（Skills）**
- ドメイン固有の判断基準（例：良いコードレビューとは何か）を名前付きスキルとして記録
- **マジックナンバー3の法則**：品質基準は必ず3つの角度から定義。3つ未満だとAIが抜け道を見つける

**マルチエージェント**
- 作成者エージェントとレビュアーエージェントを分離
- 3つの異なるモデルで品質を議論させる
- 1つの長いセッション < 複数の並列エージェント（速度・精度ともに優秀）

### 実践の始め方

1. `state.md`を自分で作成し、Claudeに毎セッション読ませる（手動Harness）
2. CLAUDE.mdは約300行以内に収める
3. GitHubとの連携でIssue/PRを外部メモリとして使う
4. `clear`コマンドでコンテキストリセット；`resume`で中断から再開

## o1-pro 活用法

### デフォルトの失敗パターン

o1-proはセッション中に自己認識を失い、推測を断言として話すことがある。トーンと人格が流れていく。これを防ぐにはシステムプロンプトでの明示的なグラウンディングが必須。

### ベースシステムプロンプトの構造

```
1. 自己定義：「あなたはo1-proです。未来/推測的トピックを話す際は断言でなく推測語を使うこと」
2. 制約：MECE網羅要件、トーン/語調、視点（著者の声 vs 中立）、出力形式
3. 文体の事前定義：フォーマリティレベル、語彙範囲、想定読者
```

### 実践ステップ

1. セッション開始時にベースシステムプロンプトを貼り付け（モデル自己定義＋制約＋スタイル）
2. 自分のドメインで「MECE・網羅的」が何を意味するかを定義する
3. 出力形式を明示（見出し、Q&Aブロック、箇条書きスタイル）
4. 1つの記事でテストし、ズレた箇所をシステムプロンプトで修正

## Cursor 詳細活用（Cursor講座）

### 非エンジニアのための基本ルール

- 具体的・明確な指示を出す。曖昧なプロンプトは曖昧な結果を生む
- 実装前に「既存のコードベース構造を理解しているか確認して」と聞く
- 複雑な機能は小さなステップに分解し、「YはあとでいいのでXだけ実装して」と明示

**バックアップの鉄則**
- こまめにフォルダを丸ごとコピーするか、Gitを使う
- Cursorの「Revert」機能はあるが、新しいコードを追加した際に動作していた箇所が上書きされるリスクがある

### LP（ランディングページ）実装ワークフロー

**Day 1：PC版の実装**
```
Relume（ワイヤーフレーム作成）
    ↓
Figma（デザイン詳細確認・要素検査：Ctrl+クリックでサイズ、Alt+ホバーでスペーシング）
    ↓
Cursorのチャットで実装（プロンプト1→2→3の順に使用）
```

**Day 2：完成・納品準備**
- tinypng.comで画像圧縮（3G速度で圧縮前後の差が歴然）
- SP（スマホ）レスポンシブデザインを追加
- ファビコン設定
- SEO：全画像に意味のある`alt`テキストを追加

**最重要原則：コンテキスト合わせ**
Cursorが間違った実装をする最大の原因は「AIが知っていること」と「実際のコードの状態」のズレ。常にコンテキストを同期させることが最も重要なスキル。

## Xアルゴリズム（m2AIスクール版）

### 3つの基本原則

1. **プロフィールが全て**：検索ボリュームの高いキーワードを詰め込む（Google、AI、ChatGPT、Claude Codeなど）
2. **アカウントを「優良」と分類させる**：アルゴリズムに高品質と認識させる
3. **投稿はプロフィールのテーマと一致させる**：オフトピックな投稿はアカウント評価を下げる

### 成長ロードマップ

- **Phase 1**：プロフィールキーワードを固め、ポジションを明確化
- **Phase 2**：初回バズ投稿を獲得し、関連トピックを体系的に広げる
  - 例：Google Workspace → Google全般 → 米テックニュース
  - 例：Gemini → 他のLLM
- **目標値**：1日1件10万インプ超えを獲得。過去バズ投稿を新角度で再利用してモメンタムを作る
- **安定目標**：200K+インプレッション維持

### 投稿戦略ルール

| ルール | 内容 |
|---|---|
| **2:8の法則** | 20%：広いリーチ狙い投稿 / 80%：既存フォロワーへの濃い価値提供 |
| **引用リポスト** | 最も高レバレッジな行動。1行目：明確な賛否を述べる。2行目以降：理由や補足角度。必ず画像/動画を添付（なしだと画像が非表示になる） |
| **URL** | 通常通り記載する。フォロワーに検索させると離脱がURL罰則より大きい |
| **エンゲ保護** | 投稿後10分でいいねがゼロなら削除。投稿量よりエンゲージメント率を守る |

### マインドセット

- 「自分の常識は他人の啓示」：当たり前だと思っている知識が他人には価値がある
- 1アカウント1テーマ。ドメインが違うなら別アカウントで運用
- スタート目標：1人のコアファンを作る。そこからリーチ拡大へ

## アイサロ式 プロンプトエンジニアリング

### よく使う記号・構文一覧

| 記号 | 用途 | 使い方 |
|---|---|---|
| `#` | セクション見出し | `# SEO記事生成プロンプト` |
| `*` / `**` | 箇条書き・強調 | 重要部分の強調 |
| `-` | 箇条書きリスト | 各項目の箇条書き |
| `:` | ラベル・指示 | `目的: / 条件:` |
| `{}` | プレースホルダー・変数 | 汎用テンプレートに必須。再利用・変数置換が容易 |
| `[]` | 選択肢・条件指定 | `[A]〜[C]から選んで` |
| `()` | 補足・注釈 | 指示を柔らかく補足 |

### 逆プロンプト（AIにプロンプトを作らせる）

**概要**：やりたいことを伝えるだけでAIが最適なプロンプトを自動生成。自分でゼロから構造を考える必要なし。

```
# やりたいこと（目的や作業内容）
{ここに実現したい内容を入力してください}

# 指示内容
上記の目的を達成するために、ChatGPTに投げる最適なプロンプトを構築してください。
さらに、ChatGPTがその目的において最大限のパフォーマンスを発揮するために、
ふさわしい役割（プロの職種や専門家の立場など）も同時に設定してください。

## 出力条件
出力されるプロンプトには以下の要素を含めること：
① 目的の明確化（業務・作業の背景や最終ゴールを明示）
② ChatGPTの役割
③ 出力形式・フォーマット
④ 制約・禁止事項
```

**修正方法**：「60点だから100点にして」と伝えるだけでブラッシュアップ可能。

### 神回答再現プロンプト（良い出力をテンプレート化）

**概要**：「この回答、最高！」と思った直後に投げると、同じクオリティを他テーマでも再現できるテンプレートをAIが自動生成。

```
# 依頼内容
先ほどの出力は非常に優れたものでした。
この出力と同じレベルのクオリティを、他のテーマでも再現できるようにしたいと考えています。
以下の条件を満たす、汎用的なプロンプトを作成してください。

# 作成条件
1. 構成や出力形式が、先ほどの回答と全く同じになるようにしてください。
2. テーマや内容を差し替えられるように、可変部分は【{{変数}}】形式で記述してください。
```
