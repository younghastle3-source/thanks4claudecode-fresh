## 既知の異常

索引と実リポジトリのツリーを突き合わせた際に判明した、ファイル名側の既知の問題。索引を再生成するときはこれらを踏まえること。

- **Part100 の重複**: `【Part100】ボディメイクvs機能改善.md` が同一サイズ（67575 バイト）で2エントリ存在する。原因は登録ミスではなく **Unicode 正規化の違い**で、片方が NFC、もう片方が NFD で記録されているため別パスとして扱われている。生のツリーでは 87 エントリだが、NFC 正規化して重複を畳むと 86 本が実体。
- **Part 番号の重複**: `Part109` が「トレーニング学/【Part109】外反母趾とうつ病になぜなる？（後半）」と「訓練学/20260414_Part109_外反母趾とうつ病」の2箇所に存在する。同一内容が別領域に再掲されたもの。
- **Part 番号の欠落**: 28本には Part 番号が無い。これは**欠落ではなく、Part64 までは番号を付けずにリポジトリへ入れているため**（本人談・2026-09-02 確認）。つまり `-` の28本が実質 Part1〜64 の範囲にあたる。番号で引けないので、**テーマ列と領域で探すこと**。内訳は 1on1 4本 / トレーニング学 13本（部位別の機能解剖シリーズ、上半身・下半身のPUSH/PULL解説、スクワットの基本など）/ ハイパフォーマンス学 5本（運動連鎖・ジョイントバイジョイント・トレーニング構成法8アプローチ・ミールプラン）/ ポージング学 3本 / 栄養生理学 2本（回復の促進方法・有効的なサプリメンテーション）/ 特典動画 1本。
- **番号付きの範囲は Part65〜Part128**（58本・ユニーク57種）。うち **Part73 / 83 / 97 / 101 / 103 / 104 / 105 の7つが欠番**（リポジトリに未収録）。
- **ファイル名の途中切れ**: `【Part76】2人の「評価方法」と「トレーニングvol.md` と `ジョイント・バイ・ジョイント理論に基づく包括的コンディショニング（後ろ半.md` はファイル名自体が途中で切れている。テーマ列もそのまま切れた形で記録している。
- **表記ゆれ**: `(188) 【Part113】…`、`_運動連鎖に基づく…`、`【Part91】…(1).md` のように接頭辞・接尾辞のゴミが混在する。テーマ列では除去済みだが、パス列は実データのまま。

CJ Advance は毎週更新される。**手作業で追わない。同期スクリプトを使う。**

```bash
# 確認だけ（追加・削除・リネーム・出典切れを検出）
python3 .claude/skills/クロニクルジャパンcj-advance/scripts/sync-lecture-index.py

# 索引を実データに合わせて更新
python3 .claude/skills/クロニクルジャパンcj-advance/scripts/sync-lecture-index.py --apply
```

スクリプトが見るもの：

1. **新着** — リポジトリにあって索引に無いパス（`+ 新着:`）
2. **消失** — 索引にあってリポジトリに無いパス（`- 消失:`）
3. **リネーム** — 消失と新着で Part 番号が一致するもの（`~ リネーム:`）。**2026-09-02 に Part123〜128 の6本が `2026-08-21_PartNNN_...` から `【PartNNN】...` へ一括リネームされ、索引と2スキルの出典パスが全部切れた**実績がある。新着だけ追っていると必ず見逃す
4. **索引内のパス重複** — 同じパスが2行ある状態
5. **各スキルの出典パス** — `.claude/skills/` 配下の全 .md を走査し、`cj advance/...md` の参照が実在するか照合

`--apply` は `## 講義一覧` の表を丸ごと再生成し、冒頭の「件数」と「索引作成時点のツリー」も更新する。他のセクションは触らない。

**単独スキルに切り出した場合のみ**、あわせて「スキル化済みの講義」に1行追加する（ここは手動）。

> 単独スキルに切り出す基準は「反復して使う判断プロセスが含まれているか」。知識の要約にとどまるものは索引に載せるだけにして、必要なときに `gh api` で本文を読む。

### 週次の運用

毎週1回スクリプトを流すだけでよい。差分が出たら `--apply` して、切り出したい講義があればそのとき判断する。
