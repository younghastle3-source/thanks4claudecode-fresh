# Threads 7日間投稿サイクル

## サイクル全体の設計思想

```yaml
基本の考え方: |
  7日間で「信頼の積み上げ→申し込みへの自然な流れ」を1サイクルとして回す。
  毎週同じ型を繰り返すことで、フォロワーが無意識に次の投稿を期待するようになる。
なぜこの順番か: |
  Day1〜2: まず「わかってくれる人だ」「そうか、このサービスが必要なんだ」と感じてもらう
  Day3〜5: 「いいな」「信頼できる」を積み上げる
  Day6:   「この人から買いたい」という感情的なつながりを作る
  Day7:   信頼が積み上がった状態で初めて募集する
ターゲット: サービス系個人事業主（ベビマ先生・フォトグラファー・コーチ・カウンセラー等）
```

---

## Day1：お客様の悩みに寄り添う投稿（共感）

```yaml
目的: 「この人わかってくれる」を作る
なぜ最初か: |
  信頼の出発点は「共感」。まず相手の気持ちを受け止めることで、
  その後の投稿を読んでもらえるようになる。
伝えること:
  - お客様が今感じている不安・迷い・葛藤
  - 「気になってるけど勇気が出ない」
  - 「本当はやってみたいけど、うちの子（私）には無理かも」
  - そう思う理由・背景への理解
  - 「大丈夫だよ」という安心感
書き方のポイント: |
  その気持ちをなぜそう感じるのか深く考えてから言葉にする。
  上から教えるのではなく、隣に寄り添う感覚で書く。
```

---

## Day2：サービスがなぜ大事なのかを伝える投稿（必要性）

```yaml
目的: 「あ、このサービスってこんなに大切なんだ」と気づかせる
なぜ2日目か: |
  共感で「わかってくれる人だ」と思ってもらった次のステップ。
  悩みを放置するリスクを伝えることで、サービスへの必要性を自覚してもらう。
伝えること:
  - その悩みを放っておくとどうなるか（リスク・機会損失）
  - だからこのサービスが必要である理由
業種別の例:
  ベビマ先生: 「触れられる時間は今しかない」
  フォトグラファー: 「今の姿は今しか残せない」
  コーチ: 「先延ばしにするほど遠回りになる」
書き方のポイント: |
  脅すのではなく、「だからこそ今がチャンス」という前向きなトーンで締める。
```

---

## Day3：サービスを受けた後の未来を見せる投稿（ベネフィット）

```yaml
目的: 「いいな」「そうなりたいな」と思える未来を見せる
なぜ3日目か: |
  リスク（Day2）を伝えた後は、ポジティブな未来でバランスを取る。
  「問題がある」→「こんな未来が待っている」の流れで行動意欲を高める。
伝えること:
  - サービスを受けたらどんな気持ちになれるか
  - どんな変化が起きるか
  - どんな時間・体験が手に入るか
書き方のポイント: |
  抽象的な「幸せになれます」ではなく、
  具体的なシーン・感覚・言葉で描写する。
  例: 「赤ちゃんがニコッと笑った瞬間、あ、これだって思えた」
```

---

## Day4：お客様に役立つ情報を出す投稿（専門性）

```yaml
目的: 「この人プロだ」という専門家としての信頼を作る
なぜ4日目か: |
  感情的な信頼（Day1〜3）に加え、知識・専門性への信頼を積み上げる。
  両方揃うことで「安心して任せられる」につながる。
伝えること:
  - よくある質問への回答
  - 自分がお客様だったら知りたいこと
  - ちょっとした豆知識・気をつけてほしいこと
難しく考えなくてOK: |
  「当たり前すぎる」と思うことでも、
  お客様にとっては知らないことがほとんど。
  自分の専門知識の「常識」を惜しみなく出す。
```

---

## Day5：お客様の声を魅せる投稿（社会的証明）

```yaml
目的: 第三者の言葉で信頼を最大化する
なぜ5日目か: |
  自分の言葉だけでは「自己アピール」に見えることがある。
  お客様の声は第三者の証言として最も信頼性が高い。
伝えること:
  - 実際に受けた人の変化
  - 受ける前と後の違い
  - 感想・喜びの声
  - どんな人に届いたのか
ない場合の対処法:
  - モニター価格での体験募集で声を集める
  - 受講生・お客様に感想メッセージをお願いする
  - 自分が別サービスを受けた時の感想を代わりに載せる
```

---

## Day6：サービスを始めた理由や大切にしていることを書く投稿（想い・ストーリー）

```yaml
目的: 「この人から受けたい」という感情的なつながりを作る
なぜ6日目か: |
  翌日の募集投稿（Day7）の前に、最も深い信頼を作る日。
  ストーリーと想いは論理を超えて人の心を動かす。
伝えること:
  - なぜこの仕事をしているのか
  - どんな想いでお客様と向き合っているのか
  - 自分自身の過去の経験・転換点
  - 大切にしている価値観
注意点: |
  ただの自己紹介にならないように。
  「私はこんな人です」ではなく、
  「だからあなたのことを本当にわかりたいと思っている」
  につながるストーリーとして書く。
```

---

## Day7：募集投稿（クロージング）

```yaml
目的: Day1〜6で積み上げた信頼を前提に、自然な申し込みへ誘導する
なぜ最後か: |
  信頼が積み上がっていない状態での募集は「売り込み」に見える。
  6日間かけて信頼を作った後だからこそ、募集が「お知らせ」として届く。
必ず含める3点:
  商品内容: 何をするのか・どんなサービスか
  得られる未来: 受けた後どうなれるか・どんな変化があるか
  申し込み方法: どうやって申し込めばいいか（LINEへ/DMへ/リンクへ）
書き方のポイント: |
  商品の詳細スペックより「どんな未来が得られるか」を先に書く。
  「申し込みはこちら」で終わらず、申し込む人が不安なく次の行動を取れるよう
  具体的な手順を書く。
NG例: 「◯月◯日〜募集開始！詳細はプロフへ」（未来も方法も不明）
OK例: 「〜な未来を一緒に作りたい方へ。◯◯コースの募集です。受け取れるのは〜です。
       申し込みはプロフのLINEから『体験希望』とメッセージしてください」
```

## 相談対応パターン

### パターンA：今週の投稿7本を一気に作りたい
```
使う情報: サービス内容・理想のお客様・過去のお客様の声・始めた理由
出力: Day1〜Day7の投稿文7本（各Day の型に沿って作成）
```

### パターンB：特定のDayの投稿だけ作りたい
```
使う情報: そのDayに対応するサービス・体験・声の情報
出力: 指定Dayの投稿文1本（型と意図を反映）
```

### パターンC：募集投稿（Day7）を作りたい
```
必ず確認する3点: 商品内容 / 得られる未来 / 申し込み方法
出力: 3点を全て含む募集投稿文
```

### パターンD：ネタはあるけどどのDayに使えばいい？
```
確認: そのネタが「共感・必要性・未来・専門性・証明・想い・募集」のどれに当たるか
出力: 適切なDayと、そのDayの型に合わせた加工提案
```
