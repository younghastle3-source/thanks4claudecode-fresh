## 第1章：マーケティングの基礎

### マーケティングの定義（2024年改定）
- **旧**：市場創造活動（売上を作ること）
- **新**：顧客や社会と共に価値を創造し、その価値を広く浸透させる活動
- 重点が「売るための施策」から「**関係構築**」へシフト

### マーケティング vs セールス
- **マーケティング**：売れる・売れ続ける仕組みを作ること（長期）
- **セールス**：目の前の顧客に商品を売る行為（短期）
- 優れたマーケティングがあれば、セールスは容易になる（あるいは不要になる）

### 3大フレームワーク

**① 3C分析（必ずこの順で）**
1. Customer（顧客）：ニーズ・購買心理・市場規模
2. Competitor（競合）：強み・弱み・シェア・戦略
3. Company（自社）：上記を踏まえた強み・差別化要因

**② STP戦略**
- Segmentation：市場を属性・心理で細分化
- Targeting：自社の強みが活きるセグメントを絞り込む
- Positioning：競合との違いを明確にし、顧客の脳内にポジションを確立

**③ 4P・4C分析**

| 4P（企業視点） | 4C（顧客視点） | 整合性のポイント |
|---|---|---|
| Product（製品） | Customer Value（顧客価値） | 顧客にとっての価値は何か？ |
| Price（価格） | Cost（顧客コスト） | 時間・手間含む総コストに見合うか？ |
| Place（流通） | Convenience（利便性） | 入手しやすいか？ |
| Promotion（販促） | Communication（対話） | 一方的宣伝ではなく対話になっているか？ |

## 第2章：顧客理解とリサーチ

### リサーチ3手法の使い分け

| 手法 | 特徴 | 向いている場面 |
|---|---|---|
| **アンケート** | 定量データ。全体傾向・ボリューム把握 | 仮説の裏付け、大量データ収集 |
| **インタビュー** | 定性データ。「なぜ？」の深掘り | 行動の理由・予想外インサイト発見 |
| **観察** | 無意識の行動を発見 | 購買シーン分析、未自覚ニーズ発見 |

**重要**：言葉（アンケート回答）と行動（実際の購買）は矛盾する。迷ったら行動を信じる。

### ペルソナ設定の鉄則
- 「30代女性」ではなく「〇〇に悩む山田花子さん（32歳）」まで具体化
- フォーマット：名前＋属性＋心理＋3つの核心的悩み＋情報収集源＋購買基準＋7段階ジャーニー＋「これは私のことだ」一言
- ターゲットを広げると誰にも刺さらなくなる

### カスタマージャーニーマップ
- **横軸**：認知→検討→購入→利用→推奨
- **縦軸**：顧客の行動・思考・感情・タッチポイント・課題

## 第3章：商品・サービス設計

### USP（独自の強み）開発プロセス
1. 顧客が得られる成果を言語化
2. 競合にない自分だけの独自性を特定
3. 数字で定量化（形容詞を数値に変換）
4. 30文字以内に圧縮

**USP3条件チェック**
1. 簡潔さ：1文で伝わるか
2. 具体性：「最高品質」等の曖昧表現がないか
3. 顧客視点：売り手ではなく顧客のメリットか

### 機能 vs ベネフィット（黄金の伝え方）
```
✗ 機能説明：「〇〇機能があります」
✓ ベネフィット表現：「[ベネフィット]になれます。なぜなら[機能]があるからです」
```

### 価格戦略3つのレンズ
1. コスト基準（コスト＋利益）
2. 顧客価値基準（この成果のために何を払うか）
3. 競合参照（市場価格帯）

**絶対ルール**：値下げスパイラルに入るな（値引き→利益低下→品質低下→離脱→さらに値引き）

### オファー設計
- 商品単体で売るな。ボーナス・保証・制限をセットにして断りにくい構成にする
- 希少性・緊急性（期間限定・数量限定）で損失回避心理を使う

## 第4章：集客チャネル

### チャネルの分類

| タイプ | チャネル | 特性 |
|---|---|---|
| **ストック型** | SEO・YouTube | 構築は遅いが資産化する |
| **フロー型** | X・Instagram・TikTok | 早くて広がるが継続投稿必須 |
| **有料型** | リスティング広告・Meta広告 | 即効性あり。止めると止まる |

### 8チャネル別指針

- **SEO**：潜在ニーズ層に届く。良質コンテンツが6〜12ヶ月で複利化
- **MEO**（Googleマップ）：実店舗必須。Googleビジネスプロフィール＋写真＋口コミが鍵
- **X（Twitter）**：有益情報＋人間性＋テーマの一貫性の3つで成功
- **Instagram**：視覚的ブランド一貫性（色・トーン統一）。発見タブからの流入
- **TikTok**：最初の3秒でフック。YouTube Shorts・Instagramリールへの転用
- **YouTube**：最も深い信頼構築。「教育コンテンツ・売らない」が基本。顔出しでファン化
- **リスティング広告**：購買意欲の高い顕在層を狙う。止めると即効果消滅
- **Meta広告**：潜在ニーズ層を属性・興味関心でターゲティング。AI最適化活用

### チャネル戦略の原則
- 役割分担：「SNSで認知、YouTubeで信頼、SEOで検索」
- 1ソース多展開：一度動画を作り複数プラットフォームに配信
- まず1チャネルで成果を出してから横展開

## 第5章：販売動線と信頼構築

### セールスファネル5段階
1. 認知 → 2. 興味（自分ごと化）→ 3. 比較検討 → 4. 購入 → 5. 継続・ファン化

各段階のコンバージョン率を1%改善するだけで全体売上は複利的に増加する。

### LP構成（久保田式4セクション）
1. **ファーストビュー（見出し）**：「誰の・どんな問題を解決するか」を即座に明示
2. **共感・問題提起**：読者の痛みを鏡のように映し、問題を意識させる
3. **解決策・ベネフィット**：商品をその答えとして提示
4. **CTA（行動喚起）**：ボタン1つ・選択肢1つ。複数CTAは絶対NG

### 信頼構築3本柱

| 柱 | 内容 | 実績ゼロの場合の代替手段 |
|---|---|---|
| **実績（客観的証拠）** | 事例・お客様の声・ポートフォリオ | 無料モニター（声と引き換え）、自分自身を実験台に |
| **共感（ストーリー）** | 失敗談・原点・ミッション。感情的つながりを作る | 自分のビフォーアフターを語る |
| **一貫性** | メッセージ・価値観が一度もブレないこと | 約束を守り続けること |

### リードナーチャリング
- LINE公式・メルマガ：価値提供→信頼構築→セールスの順序を守る
- 法則：GIVE → GIVE → GIVE → ASK

### コピーライティング心理トリガー
- 損失回避：「本日限り」「残り3席」
- 社会的証明：「満足度98%」「100社導入」
- 具体性：「作業時間が半分に」vs「高機能」（形容詞より数値）
- 説得ではなく確信：プッシュせず事実を提示し「これが必要だ」と読者自身が結論づけるよう設計

## 第6章：戦略立案と実行

### 戦略策定5ステップ
1. 現状把握（今どこにいるか）
2. ギャップ・課題抽出
3. 目標設定（数値目標）
4. 戦略設計（ロードマップ）
5. 施策実行（具体的行動）

### 事業規模別の戦略指針

| 規模 | 核心戦略 | 優先レバー |
|---|---|---|
| 個人・フリーランス | 選択と集中＋既存顧客 | LTV最大化。USP×チャネル×動線をシンプルに |
| 中小企業 | 短期収益＋長期ブランド構築の両立 | 刈り取りとブランディングを切り分ける |
| 個人コンテンツホルダー | 信頼の収益化 | 基盤固め→認知→ファン化→収益化の順序を守る |

### KPI管理

- **結果指標**（売上・件数）：コントロール不可。参考にするだけ
- **行動指標**（投稿数・アプローチ数）：コントロール可能。これを管理する
- 目標未達時：「なぜ5回」分析で根本原因を探る
- サイクル：日次確認 → 週次トレンド → 月次評価

### 高速PDCA
- ルール：「小さく・早く」。検証前に大きく投資しない
- 実行→観察→修正のループで「肌感覚」を身につける

## 久保田式メソッドの核心（7つの注意点）

1. 順序を絶対に守る（認知→仕組み化、飛ばすと崩壊）
2. 「やらないこと」の決定が最重要
3. 数字で測る。直感だけに頼らない（週次・月次の改善サイクル）
4. 顧客インサイトは観察＋仮説検証で得る。アンケートだけでは不十分
5. 価格は価値から決める。値引きをデフォルトにしない
6. AI時代のモート（堀）は機能ではなくストーリーと人間性
7. LTV > 新規獲得。最初の体験を磨き、紹介の仕組みを作る

## 7つの失敗ポイント（添削時に常に意識）

| 失敗 | 改善策 |
|---|---|
| 完璧主義で動けない | 60点でリリース。失敗をデータとして扱うMVP思考 |
| ターゲットを広げすぎ | 超具体的ペルソナ1人に絞る。拡張は後から |
| 競合分析に消耗 | 自分の差別化に集中。「本当の競合」は顧客の注意を奪うもの全て |
| リサーチが活かされない | 仮説ベースで設計。調査結果を必ず次のアクションに落とし込む |
| 施策の詰め込みすぎ | 最重要施策3つに絞る。80/20を適用 |
| KPIが曖昧 | SMART基準で設定。先行指標を追う |
| GIVEなしのASK | GIVE→GIVE→GIVE→ASK。ストーリーと価値で先に稼ぐ |

## LISAセミナー（10月合宿）追加ナレッジ

### マイクロインフルエンシング理論（マイキーさん）

**原則**：大勢を集めるより少数の高質なファンを狙え。

- フォロワー10万人以下 vs 25万人以上では、1人当たり消費単価が**40倍**異なる（実証データ）
- LLM（大規模＝平均値）よりSLM（小規模＝精鋭）。ChatGPTは100万人の平均値
- 100人が各1万円の予算 vs 100人が各1億円の予算 → 人数でなく人の質を狙え

**「集めて削る」ファン濃縮サイクル**
```
認知拡大（多数にリーチ）
    ↓
あえて都合の悪い情報・本音を発信（ふるいにかける）
    ↓
本当に共感した少数の濃いファンが残る
    ↓
この層への成約率は90%超に
```

---

### 広告戦略：認知先行・広告後付けの法則（マイキーさん）

**原則**：商品完成直後に広告をかけると2〜3年目にROIが37%マイナスになる（INSEAD・北京大学データ）。

**正しい順序**
```
先に2〜3万人の口コミファン基盤を作る
    ↓
ファンからの有機的な広がりで認知形成
    ↓
その後で広告をかける（ROIが大幅に改善）
```

**囲い込み先行の成功事例**
- Microsoft/ChatGPT：BtoB顧客に2年間限定展開してから公開
- BYD：EVを直接売らずバスで認知を上げ、数年後に自動車参入
- テスラ：広告なしでファン構築を優先

**コンセプト一貫性の原則**：コンセプトを頻繁に変えるな。1つのサービスを延命させる方が次の事業への橋が立てやすい。

---

### 集客の本質定義（LISAセミナー）

- **集客の本質**：自分（個人）にファンをつけるのではなく、**商品・サービスにファンをつける**こと
- **マーケティングの本質**：接点を持った人が**自ら購入したいという状態を作ること**（押し売りではなく状態設計）
- **センターピン**：今この瞬間に最も力を入れるべき最重要要素。時期によって変わる。上手い経営者はこれを見極める

---

### 攻撃的LP運用戦略（小笠原さん）

**原則**：1枚のLPで守るのは不可能。複数のLPを同時に回すのが正解。

- 8枚のLPを同時稼働。1枚が落ちる前に他でカバー
- A/Bテストを常時回しているから落ち始めに気づける
- **LP防御 < LP攻撃**：攻撃が最大の防御

**二段階営業（資料請求型広告）**
```
1回目：問題定義（現状 vs 理想のギャップを明確化）
    ↓
    ※「問題がなければ売れない」
2回目：解決策の提示（セールス許可を取ってから売る）
```

**アクティブ層を狙うキーワード設計**
- 「成功」「勝利」「チャレンジ」「達成」など購買意欲の高い言葉をLPに使う
- CPA12,000円で予算500〜1000万円層を獲得できる事例あり

**資料請求型広告の基準値**
| 指標 | 基準値 | 下回ったら |
|---|---|---|
| 通電率 | 80% | 電話アプローチを見直す |
| 着席率 | 43% | アポ取りトークを改善 |
| 成約率 | 10%以上 | 以下はマーケ起因と判断 |

**コミュニティ設計の逆張り価格戦略**
- 月1万円など意図的に安価に設定 → まがいものコンサルへの嫌がらせ
- バックエンドなしで全て解決するビジネスモデルにする
- 参加条件は収入不問、学習意欲と行動力（意思決定のスピード）のみ

## 集客の5段：認知・信頼・相談・受注・継続

一人で仕事をする人にとって、AIで浮いた時間の受け皿は新規事業ではなく自分の集客しかない。会社員と違い、空いた枠を渡す先の部署がないからだ。

集客が来ない理由は、たいてい5段のどこかで詰まっているだけで、詰まりの箇所を特定するのが打ち手より先に来る。

| 段階 | チェック内容 |
|---|---|
| 認知 | そもそも見つけてもらえているか |
| 信頼 | 見つかった後に調べられても大丈夫か |
| 相談 | 問い合わせの心理的ハードルが低いか |
| 受注 | 金額と条件への不安を潰せているか |
| 継続 | 終わり方が次の機会につながっているか |

- 集客は今月の売上に直結しないため、意識せず放置すると必ず後回しになる。優先順位ではなく順番の問題として捉える
- 同じ段で詰まっている人ほど自分では気づきにくい。得意な段は疑わない癖があるため、外からの点検が要る
- 出典：MIT Project NANDA「The GenAI Divide: State of AI in Business 2025」（2025年7月）。生成AIを導入した企業の95%が損益で測れる効果を出せていない
- 投稿を1日落としただけでアカウント全体の表示回数が普段の4分の1に落ちた実測がある。発信の空白は想像以上に響く

## 浮いた時間の置き場所（AIを入れても売上が変わらない理由）

パーソル総合研究所の2025年10月調査（全国の就業者対象）では、生成AIを業務で使っている人は32.4%（推計1,840万人）、業務時間はタスク単位で平均16.7%減（週26.4分）というデータが出ている。

問題はその後の使い道で、削減できた時間の61.2%が「仕事をする」ことに戻り、そのうち75.4%が日常業務に費やされている。空いた枠はすぐに元の仕事で埋まる。

- AIが速くできるのは手順が決まっている作業だけで、やり方が決まっていない仕事は投げても答えが出ない
- 空いてから何をするか考えると必ず日常業務に取られる。渡す前に行き先を予約しておく順番にする
- 日常業務は浮いた時間の使い道として書かない。ここに入れた瞬間、AIを入れる前と同じ密度に戻る
- 売上を動かすのは今やっていない仕事に充てる時間であり、日常業務でも休息でもない3つ目の使い道が肝になる

浮いた時間の予約シート（週次で4つ決めるだけ）:

1. AIに渡す作業を1つに絞る。毎週やっていて手順が決まっていて判断がほぼ要らないもの
2. 浮く時間を週◯分で見積もる。最初の目安は週30分
3. その時間に何をやるかを先に決める。当てるのは今やっていない仕事のみ
4. 曜日と時刻まで確定して予定表に入れ、人との約束と同列に扱う

- まず4週間だけ回してから、渡す作業を増やすかどうかを判断する
- 急ぎの予定が入っても枠は消さない。今週の別の時間に動かし、どうしても無理なら15分に縮めてでも残す

## SNSの数字は3つだけ見る：床・倍率・エンゲージ率

毎朝5時にGASが5媒体（Threads/Instagram/YouTube/X/TikTok）の数字をスプレッドシートに1行足し、5時35分にAIがまとめタブを読んで前日比・倍率・床を判定し、6時前にチャットへ届く仕組みにする。スプレッドシート自体は開かない運用が理想形。

見る数字はこの3つだけに絞る。

| 指標/ルール | 内容 |
|---|---|
| 床 | 最低限見られていてほしい数。目安はX 5,000インプ／Threads 1万インプ／YouTube 1,000再生／Instagram 10万再生 |
| 倍率 | インプをフォロワー数で割った値。10倍を超えたらバズ扱いにし、勝った型は負けるまで繰り返す |
| エンゲージ率 | （いいね＋リプ＋リポスト＋引用＋ブックマーク）÷インプ。1%未満で詰まり、1〜3%で改善、3%超で勝ち |
| 健全性の見方 | 直近5本のうち4本が床を超えていれば健全。超えなければ中身より先に露出量を直す |
| 比較対象 | 他人のアカウントではなく、直近1週間の自分の平均とだけ比べる |
| 指示文 | 忖度するな。ダメな数字はダメと言え。捏造するな、を1行必ず入れる |
| 作る順番 | 手動で1回→毎朝コピペ→自動化の順。逆にやると間違った形が毎朝正確に届く |

- AIに渡すのは数字そのものではなく判定の基準。基準を先に渡すと出力が分析ではなく判定になる
- 出力は3行に縛る。長い分析は読まれないので、無いのと同じ扱いになる

失敗の実例（載せてよい教訓）:
- 開発者アカウントのクレジット切れでXの数字が止まっていたのに1週間以上気づかなかった
- GASの実行時間制限で朝の処理が途中で落ちたことがある
- 止まること自体より、止まったことに気づけないことのほうが怖い。成功でも失敗でも必ず報告を届かせる設計にする

## 前提を更新し続ける回路（初日がいちばん賢いAIにしない）

総務省の情報通信白書によれば日本企業の生成AI利用率は68.9%で、もう「使っていない」段階の話ではない。それでも成果につながらないのは、前提を渡した後に更新していないからだ。

前提を渡して放置すると、そのAIがいちばん賢いのは渡した初日になる。1週間では気づかないが、3週間経つと「前より使えなくなった」と感じ始める。ここでモデルを乗り換えたりツールを変えたりするのは全部外れで、原因ではない。落ちているのはAIの性能ではなく、前提が止まっている間に現実のほうが先へ進んでいるだけ。

覚える仕組みの3部品（この順で回る。1つ欠けると初日がいちばん賢いままになる）:

1. 前提の保管場所を1か所に決める。ファイルを2か所に分けるとどちらも更新されなくなる
2. 結果を毎回、数字で受け取る。感想では回らない。指標は1つに絞り、増やすと見なくなる
3. ずれた前提をその場で書き戻す。「あとでまとめて」をやると、その回の学びごと消える

書き戻しは2行で足りる。1行目は何がずれたか、2行目はファイルのどこをどう変えるか。

- 書き戻しの材料は3つ。前回立てた読み／今回の結果の数字／その間に実際にやったこと
- 条件は4つ。指摘は1つに絞る／材料に無いことは推測しない／道具や仕組みの名前を原因にしない／最後に前提ファイルの書き換え箇所を1行で示す
- 月に1度、前提を捨てる日を作る。1か月守れなかったことが1度もない行はもう身体に入っているので消す

症状別早見表:

| 症状 | 打ち手 |
|---|---|
| 前より使えなくなった気がする | 前提ファイルの更新日を確認する。1か月動いていなければそこが原因 |
| 答えが当たり障りない | 実際にやったことの材料を厚くして投げ直す |
| 指摘が多すぎて動けない | 「1つに絞る」条件が入っているか確認する |
| モデルやツールが原因ではないか疑いたくなる | 道具の名前を原因にしないという条件を足す |
| 書き戻しが続かない | 分量を2行まで削る |
| ファイルが長すぎて読まれない | 守れている行を消す |
| 数字より先に企画してしまう | 数字を先、企画を後に順番を固定する |

## マーケの判断基準20行（AIに最初に渡すテキスト）

Claude Codeで最初に効いたのはコードではなく、判断基準を書いたテキスト1枚だった。仕様や手順ではなく、何を見て何を捨てるかという基準を書くと、返ってくる内容が一般論から判定に変わる。

書く前に紙へ3つだけ書き出す。

1. 今いちばん増やしたい数字
2. 今いちばん見て落ち込む数字
3. 先月やめた打ち手

この3つが書けなければ、基準がまだ自分の中にできていない証拠。

20行の6区分（上ほど変わらないものを書く。この順序を崩さない）:

| 区分 | 書く内容の例（おっくんの商売に置き換えた形） |
|---|---|
| 扱う仕事 | 業種はパーソナルトレーナー。主な集客はInstagram・Threads。ゴールは無料相談の予約、その先は入会 |
| 見る数字 | 最優先はDM・予約数。次にプロフィールアクセス数。いいね数は参考値にとどめる |
| 見ない数字 | 表示回数だけでは良し悪しを判断しない。1週間より短い増減は誤差扱い |
| 決め方 | 数字が落ちた原因の候補は3つまでに絞る。候補ごとに30分以内で試せる打ち手を1つ挙げる |
| 話し方 | 忖度はしない。悪い数字は悪いと言う。推測で埋めない。褒め言葉は要らない |
| 出し方 | 結論を1行→根拠の数字→明日やること1つ。全体で400字以内に収める |

運用ルール:

- 基準は短いほど強い。20行を60行に増やしたら返答が薄くなった。条件が増えるほど全部を浅く満たそうとする
- 守るのは1行1判断だけ。迷ったら足すのではなく削る
- 見直す頻度は月に1回に固定する。毎日触ると、何が効いたのかが逆に見えなくなる
- 1回で完成させようとせず、空欄のまま回して、引っかかった点をそのまま次の1行にする
- 渡す数字は雑な形のままでよい。整えるのは人の作業であり、そこを人がやっている限り時間は浮かない
- 毎週やっている作業から選ぶ。月1のものは基準を鍛える回数が足りず育たない
- 手動で1回→毎朝コピペ→自動化の順で作る。コピペが続いたものだけ自動化する価値がある
- うまくいっているかの判定は、返ってきた内容に反論したくなるかどうか。なるほどで終わる日が続いたら基準が緩い
- 出力が滑った日は指示を足さず、基準のどこが抜けていたかを疑う。原因はだいたい見ない数字が空／ゴールが古い／出し方の上限がないの3つ
- 基準は自分の頭の写しなので、自分だけでは穴に気づけない。人に見せると伸びる

## AI参謀に変える5行（褒めるだけのAIをやめさせる）

「うちの集客どうしたらいい」とAIに聞いて、当たり障りのない正解が返ってきても、翌日の行動は変わらない。悪いのはAIではなく渡し方のほうで、会話の先頭に貼る5行の縛りで結果が変わる。

1. 忖度させない。良い点より先に、まずいところから言わせる
2. 数字を見せたら、ダメな数字はダメだと言わせる。慰めさせない
3. 知らないことは知らないと言わせる。それらしい数字を加工して作らせない
4. 判断する材料が足りないときは、答える前にこちらへ質問させる
5. 結論から書かせ、理由は短く区切る

各行の意図（4行目がいちばん効く。他の4行が出力の質を上げるのに対し、4行目だけが入力の質を上げる）:

- 1行目：褒められた瞬間にこちらの思考が止まる。順番を先に指定するだけで別人の出力になる
- 2行目：数字を見せるとAIは必ずフォローを入れてくる。目標に届いたかどうかだけを基準にする
- 3行目：出典のない数字をクライアント資料に混ぜない実務的な行
- 4行目：AIを質問する側に回らせると、こちらの前提が掘り出される
- 5行目：長い理由文は読まれなくなる。読まれないプロンプトは無いのと同じ

渡す材料は3点（設定より材料のほうが出力を変える）:

- 数字の実物を加工せず渡す。要約した時点でこちらの解釈が混ざり、想像を超える指摘が出なくなる
- 過去の勝ちと負けを両方渡す。勝った案の共通点を先に言語化させる。負けの輪郭がないと勝ちの輪郭も決まらない
- やらないことの線引きを先に伝える。制約が多いほど実行できる案しか出なくなる

回し方は事実を施策より先に聞くのが肝:

1. 5行を貼る
2. 数字の実物と制約を渡す
3. いきなり施策を聞かず、まず数字から読み取れる事実だけを並べさせる
4. 出てきた事実のうち、自分が知らなかったものだけを選ぶ
5. それについてだけ、次にどうするかを聞く

出力が薄いときの戻し方は、書き直させるのではなく「渡した数字のどれを根拠にしたのかを行ごとに書け」と返す。根拠を書けない行が、薄かった箇所の正体になる。

反論の取捨:
- 忖度をやめさせると、次は何にでも反対してくるフェーズが来る
- 判断基準は1つ。こちらの渡した数字を根拠にした指摘かどうか
- 一般論を根拠にした反論は捨て、自分の数字を根拠にした反論だけ受け取る

## AIに集客を手伝わせるときのプロンプト設計原則

記事4・5・6・7に共通する設計の考え方をまとめておく。プロンプトの文面より、この5原則を守れているかのほうが効く。

- 渡す材料は絞る。多いほど良いと錯覚しがちだが、材料が増えるほどAIは無難な平均値を返す
- 推測を禁止する一文を必ず入れる。入れないと材料にないことまで補って書いてくる
- 答えは1つに絞らせる。複数出させると人は必ずいちばん楽なものを選んでしまう
- 道具の名前を原因にさせない。ここを空けておくと高確率でツールを買う話にすり替わる
- 終わったときの判定を数字で書かせる。これがないと、やった気持ちだけが残って翌月に積み上がらない
- どれも共通するのは、判断の基準を先に渡してから数字を渡すという順番。逆にすると一般論しか返らない
