# Threads集客7日間ワーク・スキル

## 核心哲学

```yaml
大切なのは投稿数ではない:
  問うべき7つの問い:
    1. 誰に届けるのか
    2. なぜあなたにお願いする理由があるのか
    3. どんな商品・サービスを届けているのか
    4. プロフィールでそれが伝わっているのか
    5. 固定投稿でサービスの内容が伝わっているのか
    6. 申し込み前の不安を解消できているのか
    7. 投稿から申し込みまでの流れがつながっているのか

土台なき投稿の末路: |
  この土台が整っていないまま投稿を続けても、
  読まれるだけで終わったり、いいねはついても申し込みにつながらない。
  投稿数を増やす前に、土台と導線を整えることが先決。

逆転の発想: |
  発信の土台と導線を整えるだけで、Threadsは
  「なんとなく投稿する場所」→「必要な人と出会い、申し込みにつながる場所」に変わる。
```

---

## 集客導線フロー（全体設計）

```
投稿を見る
  ↓
プロフィールに行く（「この人、私に関係あるかも」）
  ↓
固定投稿を読む（サービス内容・誰向け・どんな変化・次の案内先）
  ↓
LINE / DM / 無料相談 / サービス案内へ進む
  ↓
申し込みを検討する
```

```yaml
導線が途切れるポイント:
  - 投稿が良くてもプロフィールが弱いと離脱
  - プロフィールが良くても固定投稿がわかりにくいと迷う
  - 固定投稿が良くても次の案内先がなければ申し込みにつながらない
```

## Day1：理想のお客様を具体的に決める（顧客理解ワーク）

```yaml
目的: 投稿を書くときに「この人に向けて書いている」と思い浮かべられる1人のお客様像を固める
なぜ必要か: |
  「ママ向け」「女性向け」など広い言葉のままだと投稿の言葉もぼんやりする。
  たった1人を具体化することで、届く言葉が変わる。
具体化の例:
  曖昧: 「起業ママ向け」
  具体A: 「子どもが小さい中で家事育児の合間に集客を頑張っているが、
           投稿しても反応がなくて自信をなくしている人」
  具体B: 「サービスはあるが誰に向けて発信すればいいかわからず、
           プロフィールも投稿もまとまっていない人」
整理する3点:
  - 今どんな状況にいるか
  - 何に悩んでいるか
  - 何を望んでいるか
```

---

## Day2：あなたにお願いする理由を言葉にする（自己分析ワーク）

```yaml
目的: 「なぜあなたが届けるのか」を整理し、「あなたから受けたい」と思わせる発信軸を作る
お客様の申し込み決め手: |
  サービス内容・価格だけではない。
  「この人は私の悩みをわかってくれそう」
  「この人になら安心して相談できそう」
  「この人の言葉は信頼できる」
  「この人にお願いしたい」
  という感覚が大きな決め手になる。
Threadsの特性: |
  きれいに整った文章よりも、
  その人らしさ・本音・経験から出てくる言葉に反応が集まりやすい。
整理する5点:
  - 自分の経験
  - 想い・大切にしている価値観
  - 過去の悩み
  - お客様に届けたい未来
  - 自分にしか語れない視点
```

## Day3：自分の商品をわかりやすく整える（商品設計・サービス整理ワーク）

```yaml
目的: 「誰に」「何を」「どんな変化を届けるか」が伝わる状態に商品を整える
お客様が申し込み前に抱く疑問:
  - 「これは私向けのサービスなのかな？」
  - 「どんな悩みを解決してくれるのかな？」
  - 「受けたらどう変われるのかな？」
  - 「何をしてもらえるのかな？」
  - 「料金に見合う価値はあるのかな？」
ここが伝わらないと: |
  どれだけ投稿が伸びても「興味」だけで終わる。
整理する3点:
  - 誰に向けたサービスか
  - 何を提供するか（内容・方法）
  - どんな変化・未来を届けるか
```

---

## Day4：選ばれるプロフィールを整える（プロフィール設計ワーク）

```yaml
目的: 投稿で興味を持った人が最初に来るプロフィールを、離脱させない入口に整える
プロフィールで伝わるべき5点:
  - 何をしている人なのか
  - 誰に向けて発信しているのか
  - どんな悩みを解決してくれるのか
  - 自分に関係ある人なのか
  - 次に何を見ればいいのか（固定投稿への誘導）
プロフィールの本質: |
  ただ肩書きを書く場所ではない。
  「この人、私に関係あるかも」「もう少し読んでみたい」「固定投稿も見てみようかな」
  と思ってもらうための入口。
設計の材料（Day1〜3の成果を使う）:
  - Day1: 理想のお客様（誰に向けるか）
  - Day2: あなたにお願いする理由（なぜあなたか）
  - Day3: 商品内容（何を提供するか）
```

## Day5：固定投稿を整える（ピン留め投稿ワーク）

```yaml
目的: プロフィールから来た人が安心して次の行動に進めるよう、サービス内容と導線を固定投稿で伝える
固定投稿の役割: |
  ただの自己紹介ではない。
  サービス内容・誰に向けて届けているのか・どんな未来に連れていけるのかを伝える場所。
固定投稿がないと:
  - 「結局どんなサービスをしている人なんだろう？」
  - 「私が相談してもいいのかな？」
  - 「どこから申し込めばいいんだろう？」
  と迷わせてしまう。
固定投稿に含めるべき要素:
  - サービス内容（何をしてもらえるか）
  - 対象者（誰向けか）
  - 提供できる変化・未来
  - 申し込み前の不安の解消
  - 次の案内先（LINE / DM / 無料相談 など）
姿勢: 売り込むのではなく、必要な人が安心して次の行動に進めるように整える
```

---

## Day6：読まれる投稿文の型と需要のあるネタを見つける（リサーチ＆投稿文ワーク）

```yaml
目的: 需要のあるネタと投稿文の型を整理し、ネタ切れしない&読者に届く投稿を作れるようにする
なんとなく思いついたことを書き続けると: |
  読者の悩みとずれてしまうことがある。
読まれる投稿の4要素:
  - 読者が知りたいこと
  - 今まさに悩んでいること
  - 思わず手を止める冒頭（フック）
  - あなたの経験から言えること
2種類のアプローチ:
  即使えるネタ集: 投稿ネタカレンダー・テンプレートを活用
  自力でネタを見つける力: リサーチワークで「読者が何に悩んでいるか」を掴む
このスキルが与える力: |
  自分でも需要のあるネタを見つけられるようになる
  → ネタ切れしにくくなる
  → ただ投稿するのではなく、読者に届く投稿を作れる
```

## Day7：申し込みまでの流れを確認する（Threads集客導線チェック）

```yaml
目的: 投稿から申し込みまでの流れが自然につながっているかを確認・修正する
7日間で整えてきた土台の最終確認:
  投稿: Day6で整えたネタ・型
  プロフィール: Day4で整えた内容
  固定投稿: Day5で整えた内容
  LINE/DM/無料相談: 次のアクション先として機能しているか
  申し込み: 迷わず進める状態か
チェックの視点:
  - 投稿が良くてもプロフィールが弱くないか
  - プロフィールが良くても固定投稿がわかりにくくないか
  - 固定投稿が良くても次の案内先がないまま終わっていないか
最終ゴール: |
  必要な人が迷わず次の行動に進める状態。
  「どこに行けばいいかわからない」が発生しない導線。
```

## 相談対応パターン

### パターンA：Threads投稿を作りたい（今すぐ投稿文が欲しい）
```
確認事項: Day1〜3（理想客・自己分析・商品）が整理済みかを確認する
整理済みなら: Day6の型（フック・経験・読者の悩み・次のアクション）で投稿文を作成
未整理なら: Day1から順番に整理してから投稿文に移行することを提案
```

### パターンB：投稿しても申し込みにつながらない
```
確認事項: Day7の導線チェックを実施
  → 投稿・プロフィール・固定投稿・案内先のどこが弱いかを特定
出力: 弱い接点の改善案（Day4/5に戻って整え直す）
```

### パターンC：プロフィール/固定投稿を作りたい
```
事前に必要な情報: Day1（理想客）・Day2（自分の強み）・Day3（商品内容）
出力: 5点が伝わるプロフィール文 or 固定投稿の構成案
```

### パターンD：Threads集客の全体設計から始めたい
```
進め方: Day1→Day2→Day3→Day4→Day5→Day6→Day7の順番で1日ずつワークを実施
所要時間: 各Day 30〜60分程度
```

| 問い | Yes → | No → |

| 投稿→プロフィール→固定投稿→案内先の導線がつながっているか？ | Day7チェック完了 | 途切れている接点をDay4〜5で整え直す |
| 投稿が「いいねはつくが申し込みにつながらない」状態になっていないか？ | 投稿内容を見直す | 土台（Day1〜5）の整備が先かを確認する |
