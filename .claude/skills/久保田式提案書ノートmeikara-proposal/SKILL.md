# メイカラ 提案書ノートスキル
**出典：久保田亮のX記事2本（下調べ×骨組み）**

## 参照リポジトリ（GitHub・おっくん自身のナレッジ）

このスキルで提案の下調べ・骨組み作成を行う際は、`marketing` リポジトリ（github.com/younghastle3-source/marketing）を一次情報として参照すること。

1. `gh api repos/younghastle3-source/marketing/contents/AI_CONTEXT.md` を読み、リポジトリの構成を把握する
2. 過去の提案書・見積・LP原稿など関連しそうなファイルを `gh api` で探して読む
3. ここにある実データを優先して使い、一般論で埋めない

## いつ使うか（発火フレーズ）

- 「提案書の骨組みを作りたい」
- 「提案ノートを作りたい」
- 「提案の下調べをしたい」
- 「久保田式で提案の準備をしたい」
- 「受注と失注の提案を比べたい」
- 「NotebookLMで提案の下調べをしたい」

## 全体像：下調べ→骨組みの2フェーズ

同じノートを使い、時系列でひとつの運用としてつなげる。案件ごとにノートを分けず、まず下調べから着手する。

| フェーズ | 由来 | 目的 | 使う指示文 |
|---|---|---|---|
| フェーズ1：下調べ | 記事2 | 提案先の状況を知る | 下調べの準備プロンプト |
| フェーズ2：骨組み | 記事1 | 過去の受注・失注から提案の骨を作る | 骨組みを出す4段階の指示文 |
| 資料 | 記事1・記事2共通 | 4種類の資料を1つのノートに集約する | — |
| 順番 | 統合方針 | 下調べの出力が骨組み作りの入力になる | ステップ4→ステップ5 |

両記事に共通する運用哲学を、統合の背骨として引き継ぐ。

- 忖度させない：ダメなものはダメと言わせ、推測での断定を許さない
- 資料の外にある一般論は使わせない。資料に無いことは無いと書かせる
- ゼロから聞かず、範囲（過去の勝ちパターンや相手の公開情報）を先に渡す
- AIの出力をそのまま外に出さない。骨も数字も、最後は自分の目で確認する
- 道具そのものではなく、何を食わせたかで差がつく

## 前提：勝ちパターンは自分の過去にしかない

- フリーランス協会の「フリーランス白書2025」によると、稼げる仕事の獲得経路は1位が人脈、2位が過去と現在の取引先、3位がエージェントで、上位2つの源はどちらも過去に一緒に仕事をした相手である
- ゼロから書いた提案はどうしても一般論に寄る。その場で思い出せる直近の案件だけを材料にするしかないためで、勝ちパターンは記憶ではなく過去の文章を並べて比べてはじめて見える
- NotebookLMは2026年7月16日にGemini Notebookへ改称された（出典：窓の杜）。呼び方が変わっても、入れた資料の範囲だけを根拠に答える性質は変わらない
- いま広まっているGemini Notebookの使い方は読書だが、成果が数字に出にくく続きにくい。範囲を区切って答えてほしいという提案の下調べのほうが、この道具の性質と噛み合う
- スキルの差はAIで縮んできた。いま大きいのは作れる／作れないの差ではなく、選ばれる／選ばれないの差のほう
- 選ばれた記録（決まった提案・断られた提案・相手の言葉）は自分の手元にしかない資産であり、他の誰も持っていない
- 同じ道具を使っても、料理と同じで仕上がりに差が出る。差がつくのは道具の性能ではなく何を先に読ませたかのほう

## ステップ1：ノートに入れる資料4種類

| # | 資料 | 内容 | 目安 |
|---|---|---|---|
| 1 | 提案先の公開情報 | サイト・採用ページ・代表インタビューなど、公開されている情報をそのまま入れる | 集める時間は15分ほど |
| 2 | 受注した提案 | ファイル名の頭に受注と付けた、通った提案書と見積書 | 5件 |
| 3 | 失注した提案 | ファイル名の頭に失注と付けた、断られた提案とその返信 | 3件 |
| 4 | 相手の生の言葉 | 商談の議事録・チャットログ・録音の文字起こし。要約しないでそのまま入れる | 業界用語に翻訳しない |

- 採用ページは営業ページより本音に近い。募集職種や歓迎条件に、今の困りごとと向かう先が出やすい
- 失注した提案を混ぜないと差が出ない。受注案件だけを並べて見ると全部が良く見えてしまう
- 提案書の形が残っていなくても、送ったメールの文面やチャットのコピーで代用してよい
- 録音が無ければ商談後に自分で書いたメモでよい。無いものを無理に揃えない

## ステップ2：入れる前のマスキング3点

入れる前に、次の3点でマスキングする。

1. 会社名をA社などに置き換える
2. 金額を丸める
3. 担当者名や個人名を削る

- 守秘義務のある資料も同じ扱いにする。会社名や金額、個人名が入ったままの資料はそのまま入れない
- 相手にとっては、自分が話したことが勝手にどこかへ入るのは怖いことだと考えておく
- ここを雑にやる人は、そもそも提案でも信用されない

## ステップ3：ノートを1つ作る（入れすぎない）

- ノートは1つにまとめる。案件ごとに分けると比べる相手がいなくなり、差が出ない
- 資料は10個以内に絞る。全部の手持ち資料を入れると、誰宛でもない平均的な答えが返ってくる
- 迷ったら外す。足りなければあとから足せばいい
- 4種類そろえても30分はかからない

## ステップ4：下調べの準備プロンプト（コピペ用）

- 先頭で役割と禁止事項を渡すのは、それらしい推測で埋める癖を止めるため
- 4点目の「触れないほうがいい話題」が、失注資料から地雷を拾ってくる
- Notebookは出典を示すが、指示の側でも資料に無いことは無いと書くよう釘を刺しておく

4種類の資料を入れたら、最初に次の指示文をそのまま貼る。【　】の2箇所だけ自分の情報に書き換える。

```text
あなたは【自分の職種】の提案準備を担当する調査係です。資料に基づいて事実だけを整理してください。推測で断定しないでください。資料に無いことは「資料に無い」と書いてください。
これから【提案先の会社名】への提案を準備します。入れてある資料だけを根拠に、次の4点を出してください。
1 相手の会社がいま困っていそうなことを、根拠の資料名とセットで3つ。
2 私の過去の提案のうち、今回の相手に転用できる要素を、通った提案と断られた提案の差に触れながら2つ。
3 相手の資料に出てくる言葉で、提案書にそのまま使えそうな表現を5つ。
4 この提案で私が触れないほうがいい話題を1つ。理由も添えてください。
すべて、資料の言葉を引用しながら答えてください。一般論は不要です。
```

## ステップ5：骨組みを出す4段階の指示文（コピペ用）

- 下調べの答えを見てから貼る。3つ目の【業種・規模・相談されている内容】を埋めるのに使う
- 1つ目・2つ目の答えが薄いと感じたら、資料を足してから3つ目に進む

ステップ4の下調べが終わったら、同じノートに次の指示文を貼って提案の骨を出す。

```text
あなたは、このノートに入っている資料だけを読んで答えてください。ノートの外にある一般論は使わないでください。
1つ目。受注と付いた提案と、失注と付いた提案を読み比べて、受注したものにだけ共通している要素を5つ挙げてください。書き方の話ではなく、何を書いているかの違いで挙げてください。
2つ目。相手が実際に使っていた言葉のうち、受注につながった案件で出てきた言葉を10個そのまま抜き出してください。言い換えないでください。
3つ目。今回の相手は【業種・規模・相談されている内容】です。1つ目で挙げた共通要素と、2つ目で抜いた言葉を使って、今回の提案の骨を作ってください。見出しだけで構いません。本文はまだ書かないでください。
4つ目。その骨のうち、過去の失注案件と同じ形になっている部分があれば指摘してください。忖度はしないでください。
```

## ステップ6：4段階の読み方（4つ目が本体）

| 順番 | 何を読むか | 確認すること |
|---|---|---|
| 1つ目 | 受注にだけ共通する要素5つ | 書き方ではなく「何を書いたか」の差になっているか |
| 2つ目 | 相手の生の言葉10個 | 言い換えられていたら指示をやり直す |
| 3つ目 | 提案の骨（見出しだけ） | 本文まで出てきていたら指示を守れていない |
| 4つ目 | 失注と同じ形になっている箇所の指摘 | ここが本体で、いちばん価値がある |

- 忖度するな、ダメなものはダメと言え、という一行を必ず入れる
- 褒めるだけの返答が続くなら基準が緩い。良い言葉で終わる出力は当てにならない

## ステップ7：骨を提案書に仕上げる（判断は人がやる）

- 出てきた骨をそのまま提案書として使わない。過去の型に今回の相手を当てはめただけの状態にすぎない
- 骨を見ながら、今回だけの一行を自分で足す。相手が違えば前提も違う
- 作業の実行はAIに任せ、載せるかどうかの最終判断は自分で下す。ここの線引きを緩めないほうが、結局は早く仕上がる
- 提案書に載せる数字は、示された出典の箇所を必ず自分の目で開いて確認する
- 確認にかかる手間は1件あたり数十秒。AIが出した答えをそのまま社外には出さない

## ステップ8：週1回10分の追加運用

- 週に1回、10分だけノートの更新に使う
- 案件が終わるたびに、提案と結果をノートに追記する。ファイル名の頭に受注か失注の結果を付け足すだけでよい
- 更新を止めると、ノートは3か月ほどで古くなる
- 1年続けると、他の人が絶対に持っていない資料になる

## つまずいたときの対処

| 症状 | 原因 | 対処 |
|---|---|---|
| 骨が一般論に見える | 失注資料が入っていない | 断られた提案を足す |
| 指摘が甘い | 忖度するなの一行が抜けている | 指示文に一行を足す |
| 生の言葉が出てこない | 議事録を要約して入れている | 要約せず原文のまま入れ直す |
| 答えが誰宛でもない | 資料が10個を超えている | 迷ったら外して絞り込む |
| 何でもやりますの提案になる | 受注案件から骨を作っていない | 受注・失注の比較からやり直す |

- 何でもやりますの提案は単価を下げる。絞ると仕事が減るように見えるが、実際は逆で「何の人か分からない」のと同じ意味になる

## 小さな店・個人の告知への応用

- 小さな店や個人事業でも考え方は同じ。過去に来てくれたお客さんの反応をノートの材料にする
- 反応が良かった告知文、反応がなかった告知文の2つを入れておくと、次の告知の骨がすぐに出せる
- 反応がなかったものは外さない。外してしまうと、良し悪しの差がつかめなくなる

## 関連スキルとの境界

| 観点 | 本スキル（meikara-proposal） | 久保田式ライティングmeikara-blog の「書く前に断らせる」 |
|---|---|---|
| 入力 | 自分の過去の受注・失注・相手の生の言葉・公開情報 | 売るもの・価格・相手の人物設定 |
| 役割 | 資料の範囲内で事実を整理する調査係 | 客を演じて断る役 |
| 出力 | 下調べの4点＋提案の骨（見出し） | 買わない理由10個→3分類 |
| 順番 | 先（骨を作る） | 後（できた骨を潰しにかかる） |

- 本スキルは過去の実績から骨を出すところまでを担当する
- 骨が出たあとの「買わない理由を潰す」作業は久保田式ライティングmeikara-blog の断らせるステップへ渡す
- 忖度させない指示の系統は久保田式マーケメソッドmeikara-marketing とも共通している
