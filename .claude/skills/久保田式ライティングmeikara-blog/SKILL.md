# メイカラ式 ブログライティングスキル

## 参照リポジトリ（GitHub・おっくん自身のナレッジ）

このスキルで記事執筆・添削・リライトを行う際は、`blog.writing` リポジトリ（github.com/younghastle3-source/blog.writing）を一次情報として参照すること。

1. `gh api repos/younghastle3-source/blog.writing/contents/AI_CONTEXT.md` を読み、リポジトリの構成・性格を把握する
2. 関連するメイカラ講座ノートを `gh api` で探して読み、そこで学んだライティング原則を優先して使う

## 基本：Webライティング6つのルール

文章を書く際は必ず以下を守る：

1. **文末表現の重複禁止**：「〜です。〜です。〜です。」はNG → 表現を変える
2. **一文を短くする**：読点で区切れる文は分割する
3. **接続詞の乱用禁止**：「そして」「また」「さらに」を連発しない
4. **「〜たり〜たり」はセットで**：「〜たり、〜したりする」と必ず対にする
5. **「〜こと」の重複禁止**：同一段落内で繰り返さない
6. **冗長表現の排除**：「〜することができる」→「〜できる」、「〜という」→削除

**指示代名詞（これ・それ・あれ）は避ける**：具体的な名詞を繰り返す。

## PREP法（文章の基本構造）

```
Point   → 結論（先に言う）
Reason  → 理由
Example → 具体例・データ
Point   → 再結論（念押し）
```

## SEO記事の書き方（第3章）

### ペルソナ設定の5ポイント

記事を書く前に必ず設定する：

| 項目 | 内容 |
|---|---|
| 悩み | 読者が抱えている具体的な問題 |
| 現状 | 今どういう状況にいるか |
| 知りたいこと | この記事で何を知りたいか |
| 前提知識 | どのくらい知識があるか |
| 読後理想状態 | 読み終わった後どうなっていてほしいか |

### タイトル・メタの法則

- **タイトル**：28〜32文字（検索結果で切れない長さ）
- **ディスクリプション**：150〜160文字（検索結果に表示される要約）
- キーワードはタイトルの前半に入れる

### 見出し設計の8ポイント

1. H2は記事の骨格 → 見出しだけ読んで記事の内容がわかるか確認
2. H3はH2の補足・深掘り
3. キーワードを自然に含める
4. 疑問形・数字を活用（「〇〇とは？」「3つの方法」など）
5. 抽象的な見出しはNG（「まとめ」「について」だけはダメ）
6. 検索意図を反映させる
7. 競合の見出しを参考にしつつ独自性を加える
8. 読者の知りたい順番に並べる

### 本文執筆の要点

- **正確さ最優先**：誤情報は信頼を失う
- **一次情報を使う**：体験談・独自調査・公式データ
- **キーワードは自然に**：詰め込み過ぎはNG
- **滞在時間を伸ばす**：図解・箇条書き・太字で読みやすく

## セールスライティング（第7章）

### リンクの優先順位

```
テキストリンク > ボタンリンク（マイクロコピー付き）> バナーリンク
```

**マイクロコピー**とはボタン近くの補足文：
- 「無料で試せます」「登録30秒」「今だけ〇〇特典付き」

### 改善のやり方

- **要素は1つずつ変える**（ABテスト原則）
- PV確保が最優先 → PVなしでCVR改善しても意味がない
- データに基づいて継続改善

## リライト（第9章）

> **「書いた量ではなく、直し続けた量で勝負が決まる」**

### リライト8ステップ

1. キーワード順位確認（GSCで20位以内の記事を特定）
2. タイトル・見出しの見直し（検索意図とのズレを修正）
3. 競合リサーチ（上位記事と比較して不足コンテンツを追加）
4. 内部リンク最適化（比較記事・商標記事への導線を強化）
5. 文章・装飾調整（読みやすさ改善・太字・箇条書き）
6. 画像・図解の改善（理解を助けるビジュアルを追加）
7. 広告・リンク微調整（CTR改善）
8. インデックス再登録（GSCで「URL検査 → インデックス登録をリクエスト」）

### リライト優先度の決め方

```
高優先：11〜20位の記事（少し改善で1ページ目に入る可能性が高い）
中優先：21〜50位の記事（コンテンツ充実が必要）
低優先：1〜10位の記事（情報の鮮度更新のみ）
```

## AIに書かせるときの就業規則（7行ルール）

AIに任せた仕事が思ったように返ってこないのは、プロンプトが下手なのではなく、決めていないだけのことが多い。人を雇うときに頼み方より就業規則で揉め事を減らすのと同じで、AIにも共通のルールを1枚読ませておくと安定する。以下の7行は、実際に起きた事故のあとに1行ずつ足してきたもの。

1. 出どころを1行で言えないことは書かない。分からないときは分からないと書く（会っていない相手に取材した場面が原稿に混ざっていた事故から生まれた行）
2. 褒めるな。ダメな数字はダメだと言わせる。捏造は禁止（数字が悪い週でも安定推移と書いてくる癖に気づいて足した行）
3. 終わりの時刻を先に決めておく。間に合わない分は捨てて、できなかったと報告させる（下書きが完成予定の時刻を過ぎても、エラーの連絡もなく消えていた事故から）
4. 同じ失敗が2回続いたら、そこで止めて状況を報告させる（うまくいかない方法を粘り強く繰り返し、他の仕事を止めていた反省から）
5. 提出前に、決めた条件を機械で数えさせて結果を書き添える（人の目視チェックが3回すり抜けた事故から）
6. 判断に迷ったら、進めずに選択肢を並べて聞かせる（曖昧なまま頼んだ仕事ほど自信満々に間違えていた経験から）
7. 失敗を直したら、この規則に足す1行を提案させる（1行足すことだけが積み上げになるという発想の転換から）

- この7行は完璧に書いてから任せるものではない。先に任せて、失敗して、1行足すという順番のほうが規則が現実に合う
- 毎回の頼みごとの前に貼るだけで働く。カスタム指示や毎回読ませる設定欄があるツールなら、そこに1回入れれば済む
- 一番効いているのは2行目。気持ちよくなる報告は読み流されるが、痛い報告は行動を変える
- 使うツールはChatGPT・Claude・Geminiのどれでも同じように働く。道具の選び方より規則の中身のほうが差になる
- 規則は縛るほど窮屈になる人間の部下と違い、AIは行数が増えても嫌がらずに毎回全部読む。書きすぎより書き足りないほうを心配する
- 作業を渡すことと判断を渡すことは別。7行は「ここまでは任せる作業、ここからは自分の判断」という線を毎回引き直すための仕組みだと考える
- 数十行に増えても人間の職場のような息苦しさは出ない。AIに対しては遠慮なく足してよい
- 3行目の締切時刻だけは仕事ごとに書き換え、残りの6行はそのまま幅広い依頼に使い回せる

---

## 規則の育て方：事故が起きた日に1行足す

就業規則を完成させてから任せようとすると、いつまでも始められない。先に任せて、事故が起きたその日のうちに1行を書き足すほうが、規則が現実に合う。時間が経つと何が起きたかは覚えていても、どう防ぐかを書く感覚のほうを忘れる。

- ルールが1行増えた日は、AIが1つ賢くなった日として数える
- 規則が増えるほど確認の手間が減り、任せられる範囲が広がる。逆説的だが実際にそうなる
- 完成しないのが正常な状態。仕事の中身が変われば、起きる失敗も変わっていく
- 増やすコツは事故当日のうちに書くこと。時間が経つと何が起きたかは覚えていても、どう防げばよかったかを忘れる
- 最初の1行は何でもいい。事故のほうが規則の中身を教えてくれる
- 数字の判断まわりで同じ発想を使う場合は、久保田式マーケメソッドmeikara-marketing の「前提を更新し続ける回路」（書き戻しの2行ルール）とセットで運用すると効果が重なる

## 提案書は書く前に断らせる（買わない理由10個→3分類）

提案書やLPをAIに「書かせる」と、誰に出しても成立するきれいな文章が返ってくる。書けと言われたAIは通すことしか考えないからだ。だから書く前に、AIに客側を演じさせて拒否の理由を先に吐き出させる。商談で出る反論は、たいてい提案書の設計ミスの答え合わせに過ぎない。

4ステップ（この順序を崩さない。順番が崩れると教科書的な内容にしかならない）:

1. **前提を渡す**：売るもの・価格・相手を盛らずに素のまま渡す。パーソナル指導なら「体験セッション◯円、相手は運動未経験の30〜40代」のように事実だけを渡す
2. **役を振る**：「客の立場で」では弱い。年齢・職業・従業員の有無・過去の失敗経験・内心まで決めた具体的な人物にする。ジム開業相談の例なら「開業資金に余裕がなく、従業員はゼロで一人運営、過去にコンサルで失敗した経験がある人」まで書く
3. **断らせる**：買わない理由を10個、正直に出させる。丁寧な断り文句ではなく、頭の中で本当に思っていることを書かせる
4. **仕分けさせる**：出た10個を3分類し、分類の理由も1行ずつ書かせる

- なぜ10個か：数を指定しないとAIは3〜4個で止まり、誰にでも当てはまる無難なものしか出さない。10個まで絞り出させると在庫を出し切るしかなくなり、後半に本音が出てくる
- 後半の本音の例：オンライン指導の相談なら「続けられる自信がない」「対面じゃないと信用できない」あたりが後半で出やすい
- 先に潰す：提案書の中で、相手が言い出す前にこちらから触れておく
- 口頭：商談の場で答える。書くと重くなるものはここに回す
- 売らない：そもそもこの客層には売らないと決める。3つ目があることが仕分けの肝
- やってはいけない使い方：出てきた10個の全部に反論を書くのはやめる。言い訳の羅列になり、読む側は「そんなに問題があるのか」と感じてしまう
- 見出しの裏技：仕分けた断り文句を、そのまま見出しに使う。「今じゃなくてもいい、と思った方へ」のように、自分の言いたいことより相手の頭の中の言葉を見出しにするほうが読まれる
- 口頭や売らないに回した分も、商談前の想定問答としてメモに残しておく。準備してある反論とその場で考える反論は、相手から見ると別物に見える
- 出力が薄いときの原因は2つ。人物設定が抽象的すぎるか、提案の説明を良く見せすぎているかのどちらか。素っ気ないくらいに渡し直すと変わる
- それでも薄いときは「今の回答は建前です。本音で答え直してください」と一言足す
- AIが出した断り文句を全部は真に受けない。判断基準は1つ、過去に実際に言われたことがあるかどうかだけで、無いものは優先度を下げる
- 断り文句は時期によって変わる。同じ商品でも定期的にやり直し、古い反論に答え続ける提案書のままにしない
- この作業は提案書だけでなく、商品を作る前の企画段階や、プロフィール・ポートフォリオの見直しにも応用できる
- 一度通った提案書は保存しておき、似た案件が来たときに「同じ構造が使えるか」をAIに判断させると、ゼロから書くより速くて精度も高い
