# Instagram PDCA スキル

> **参考アカウントの投稿から型を学び、自分の投稿のフォーマット・型・ハッシュタグを選び、実績を振り返って次に繋げるための PDCA スキルです。**
> 本スキルはフォーマット選定・型選定・実績の記録と振り返りに徹し、リール台本本文の生成は既存の台本スキルに委譲します（詳細は下記「既存スキルとの役割分担」）。

## 参照リポジトリ（GitHub・おっくん自身のナレッジ）

このスキルで投稿案作成・分析・壁打ちを行う際は、`marketing` リポジトリ（github.com/younghastle3-source/marketing）を一次情報として参照すること。

1. `gh api repos/younghastle3-source/marketing/contents/AI_CONTEXT.md` を読み、リポジトリの構成・性格を把握する
2. 相談内容に関連しそうなファイル（Be Co Gym戦略、LP原稿、メイカラ講座メモ、SNS戦略メモ等）を `gh api` で探して読む
3. 一般論より、ここにある実体験・実データ・実際に学んだ内容を優先して回答に使う

## このスキルでできること

1. 参考アカウントの投稿をコピペで受け取り、**型ライブラリ（IG-R1〜IG-S1）に統合**する
2. 伝えたい内容から**リール/フィード/ストーリーズのフォーマット**と**型**を選び、下書きの土台を作る
3. 投稿後の実績（リーチ・フォロワー外%・保存 等）を**投稿ログに記録**する
4. 投稿ログを**週次/月次で集計**し、フォーマット・型ごとの傾向を振り返って次の Plan に反映する
5. 読む側に**断らせる**（反応しない理由を出させる）ことで、下書きの精度と低反応型の原因分析を上げる

## 参照ファイル

- `references/format-guide.md`: リール/フィード/ストーリーズの使い分け・ハッシュタグ戦略・Instagram 指標の定義
- `references/pattern-library.md`: IG-R1〜IG-S1 の各型の構造・出典・主指標・効く理由をまとめた型ライブラリ
- `references/my-posts-log.md`: 自分の投稿実績を記録するログテンプレート
- `references/hook-design.md`: フック評価4軸（広さ・引き・絵・洗練）＋代表6型のフレームワーク（出典: marketing リポジトリ）
- `references/research-method.md`: 「伸びた理由の言語化→自分のジャンルへ転用」のリサーチ10ステップ（出典: marketing リポジトリ）

## ワークフロー1: 分析（新規アカウント分析 → 型ライブラリ統合）

発火フレーズ: 「インスタの投稿分析して」「このアカウントの投稿を型にして」「参考アカウントの投稿貼るね」

ユーザーが参考アカウントの投稿をコピペで手渡してきたときに実行する。Instagram API やスクレイピングは使わず、常にユーザーからの手渡しを前提にする。

1. `references/research-method.md` の10ステップに沿って、貼られた投稿が「なぜ伸びたか」を分解する（可能であれば同一アカウントの通常投稿との比較・感情から逆算する4ステップも行う）
2. 貼られた投稿を1件ずつ読み、`references/pattern-library.md` のどの型に近いかを判定する
3. 既存の型と骨格が重複する場合は、その型のセクションに新しい特徴・言い回しを**統合**する（型を増やさない）
4. 既存のどの型にも当てはまらない新しい骨格の場合のみ、ユーザーに確認した上で新しい型として追加する
5. 統合・追加した内容には、必ずその投稿の**出典**アカウント名を明記し、「効く理由」欄は手順1の抽象化結果を踏まえて記述する
6. `references/pattern-library.md` を更新し、変更点をユーザーに要約して報告する

---

## ワークフロー2: Plan（フォーマット選定→型選定→下書き）

発火フレーズ: 「インスタの投稿作って」「今日の投稿の下書きお願い」「リールとフィードどっちがいい」「ハッシュタグ考えて」

1. ユーザーから伝えたい内容・状況（日常/告知/振り返り 等）を受け取る
2. `references/format-guide.md` を参照し、リール/フィード/ストーリーズのどのフォーマットが向いているかを判断する
3. `references/pattern-library.md` を参照し、選んだフォーマットに向いている型を1つ選ぶ（複数型の組み合わせも可）
4. 下記「断らせるチェックの手順」を実行し、読む側が反応しない理由を洗い出す
5. 選んだ型の「型の構造」に沿って**下書き**を作成する。IG-R1/IG-R2 を選んだ場合、フックの言い回し・台本の文体は既存の台本スキルに委譲する
6. 生成されたフックを `references/hook-design.md` の4軸（広さ・引き・絵・洗練）＋守り・鮮度で評価し、必要なら3案（王道/強め/別切り口）を比較してから最終案を選ぶ
7. `references/format-guide.md` の `## ハッシュタグ戦略` を参照し、規模の異なるハッシュタグを組み合わせて選ぶ
8. 下書きと「狙った型」「フォーマット」をユーザーに提示し、投稿後に `references/my-posts-log.md` へ記録する旨を伝える

### 断らせるチェックの手順（手順4 / 下書き作成前）

1. 読む側の**ペルソナ**を具体的に立てる（年齢・状況・過去の失敗体験・本音の疑いまで指定する）
2. そのペルソナを演じさせ、「この投稿に反応しない・保存しない理由」を**10個**、正直に挙げさせる
3. 出た10個を3分類する: ①今回の投稿で**先に触れる** ②**触れない**（コメント返信等で対応する） ③このペルソナは今回の**ターゲット外**と割り切る
4. Instagram のキャプションも長くしすぎないため、①に選んだ1つ程度の理由だけを下書きに反映し、一番強い断り文句は冒頭かフックの直後に置いて警戒を下げる

## ワークフロー3: Check（投稿後の実績記録）

発火フレーズ: 「インスタの実績を記録して」「さっきの投稿、保存数教えて」「投稿結果を報告するね」

投稿ごとの簡易チェックとして、投稿後にユーザーから実績が報告されたときに実行する。

1. ユーザーから日付・投稿の要約・フォーマット・狙った型・リーチ/フォロワー外%/いいね/コメント/保存/シェア/プロフアクセス・気づきを受け取る
2. 情報が不足している項目（フォーマットや型など）があればユーザーに確認する
3. `references/my-posts-log.md` の投稿実績ログの表に1行追記する（既存のヘッダ・区切り行は変更しない）
4. 追記した内容をユーザーに要約して報告する

---

## ワークフロー4: Act（週次/月次の集計・振り返り）

発火フレーズ: 「インスタの振り返りして」「今週の投稿まとめて」「月次でどのフォーマットが効いてるか教えて」

投稿ごとのチェックとは別に、週次/月次でまとめて振り返るときに実行する。

1. `references/my-posts-log.md` の投稿実績ログを読み込み、対象期間（週次/月次）のデータ行を抽出する
2. フォーマット別・型（IG-R1〜IG-S1）別に実績を**集計**し、リーチ・保存・コメントなどの平均や合計を出す
3. 効果が高いフォーマット・型・低いフォーマット・型の**傾向**を分析し、気づき欄の内容も踏まえて要因を推定する
4. 実績が低い型が見つかった場合は、下記「低反応の型の原因分析」を実行する
5. 分析結果をユーザーに報告し、次の Plan（ワークフロー2）で優先すべきフォーマット・型を提案する

### 低反応の型の原因分析（断らせるチェック / オプション）

1. その低反応投稿を見る側のペルソナを具体的に立て（年齢・状況・過去の失敗体験）、そのペルソナを演じさせる
2. 「なぜこの投稿に反応しなかった・保存しなかったのか、正直な理由」を10個挙げさせる
3. 出た理由から、次の Plan で避けるべき言い回しと追加すべき要素をまとめ、ユーザーへの**提案**として提示する
4. `references/pattern-library.md` の該当型の「効く理由」欄への注記候補として提示するに留め、ファイルへの自動書き込みは行わない

## 既存スキルとの役割分担

| スキル | 担当範囲 | 呼び出す場面 |
|---|---|---|
| 本スキル（instagram-pdca） | フォーマット選定・型選定・キャプション・ハッシュタグ・実績記録・振り返り | 投稿の企画時と投稿後 |
| `.claude/skills/instagram-フック型ショート台本.md` | リールの一言目（フック）と台本の文体 | IG-R1 を選んだ後、台本を書くとき |
| `.claude/skills/instagram-日常ブリッジ台本.md` | リールの構成設計（日常→本題への導線） | IG-R2 を選んだ後、構成を組むとき |
| `.claude/skills/threads-pdca/` | Threads 側の PDCA（型ライブラリ・投稿実績ログ） | Threads の投稿を扱うとき |

本スキルはリール台本本文を書かない。台本の生成・添削は既存2スキルに**委譲**する。
`pattern-library.md` にフックの型名・文体ルールを書き写すと二重管理になるため禁止する（既存台本スキルからの写経禁止）。
Threads の型ライブラリとは統合しない（指標も最適なフォーマットも異なるため）。`instagram-pdca` は Instagram 専用の型・指標のみを扱う。

---

## このスキルの使い方

1. ユーザーからの発火フレーズに応じて、上記4ワークフローのいずれかを実行する
2. フォーマット・指標の判断には必ず `references/format-guide.md` を参照する
3. 型の判断には必ず `references/pattern-library.md` を参照する
4. 実績の記録・集計には必ず `references/my-posts-log.md` を参照する
5. リール台本本文の生成・添削は行わず、既存の台本スキル（上記「既存スキルとの役割分担」参照）に委譲する
6. 実データの自動取得は行わない。参考アカウントの投稿・自分の実績はいずれもユーザーからの手渡しを前提にする
