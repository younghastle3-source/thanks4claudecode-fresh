# フック設計フレームワーク

> **出典**: `sns/insutagram/伸びるリールのフック設計.md`（marketing リポジトリ: https://github.com/younghastle3-source/marketing）
> リール冒頭1〜3秒のフックを評価・改善するための共通フレームワーク。既存の台本スキル（`instagram-フック型ショート台本.md`／`instagram-日常ブリッジ台本.md`）が書いたフックも含め、**どのフックにも適用してよい評価軸**として使う。フックの文体・生成そのものは引き続き既存台本スキルに委譲し、本ファイルは「良し悪しの判定基準」を提供する。

## フックとは何か

フックとは**視聴者に「続きを見る理由」を与えるもの**であり、単なるタイトル（内容説明）とは違う。

- タイトル例: 「函館のおすすめカフェを紹介します」→ 説明であって続きを見る理由が弱い
- フック例: 「函館でここだけは教えたくない」→ 「なんで？」「どんな店？」という**頭の中に「？」を残す**

原則: **答えを全部言わない**。答えを言い切ると視聴者はその場で情報を得てしまい離脱する。「閉じるフック」（共感だけで完結する）ではなく「開くフック」（続きを知りたくなる）を作る。

## 評価4軸＋2つの安全確認

フック案は以下で評価する（`pattern-library.md` の各型の「効く理由」を判断する際にも流用できる）。

| 軸 | 問い |
|---|---|
| ① 広さ | 対象ユーザーが一瞬で理解できるか（専門用語・弱い固有名詞で理解コストを上げていないか） |
| ② 引き | 疑問・違和感・期待が残るか、続きを見たくなるか |
| ③ 絵 | 言葉を聞いた瞬間に映像が浮かぶか（「最高」「こだわり」等の抽象語より「高さ5cm」「1日10食」等の具体語） |
| ④ 洗練 | 無駄な言葉・重複がないか（削っても意味が変わらないなら削る） |
| 守り | 煽りすぎ・炎上リスク・ブランド毀損・誤解がないか（特にクライアント案件） |
| 鮮度 | 「9割が知らない」「知らないと損」等の擦られすぎた表現になっていないか |

**加点より減点を消す**意識で見る（「もっと強い言葉を足す」ではなく「離脱原因はどこ？」）。4軸すべて満点を狙わず、致命的な弱点がない状態を目指す。「なんか弱い」で止めず、上記6項目のどれが原因かまで言語化してから直す。

## フックの代表6型（組み合わせ可）

1. **数字・限定**: 「1日10食限定」「5kg痩せた」— 具体的で希少性を作れる
2. **否定・警告**: 「これ、やめてください」— ただし多用するとネガティブ/攻撃的に見えるので企業アカウントは注意
3. **常識破壊・ギャップ**: 「ポテチを食べたら痩せます」— 一般常識を反転させ「なんで？」を作る
4. **問いかけ**: 「店選び、失敗してない？」— 視聴者を自分ごと化させる
5. **ベネフィット**: 「絶対外さない店、これ1つ」— ノウハウ・ハウツー系と相性が良い
6. **ターゲット名指し**: 「函館旅行する人へ」— 該当者への刺さりは強いが対象外は離脱するため広さは下がる（バズ狙いか、CV狙いかで意図的に絞るかを決める）

## 抽象度の中間点を探す

「人生を変えた挑戦」（抽象的すぎ・何の話か分からない）と「○○方式の小水力発電システムを導入しました」（具体的すぎ・答えが全部分かる）の中間、**「理解できるが答えは全部分からない」地点**を狙う。

## 映像・テロップ・アフレコは役割分担する

3つを同じ情報の繰り返しにしない。例（分厚いカツ丼の場合）:
- 映像 → 視覚情報（分厚いカツそのものを見せる）
- テロップ → 感情・引き（「これ、反則です」）
- アフレコ → 補足説明（店や商品の背景）

映像だけで内容が伝わるなら、テロップの1文要約は削ってよい（映像で伝わる情報をテロップで重複させない）。

## 実践フロー

ターゲット確認 → 素材確認 → 強い素材を抽出 → 感情を決める → 疑問・余白を作る → **フックを3案作る**（A: 王道 / B: 強め / C: 別切り口）→ 4軸＋守り・鮮度で評価 → 映像と合わせる → 投稿 → 数字を見て次へ改善。

フックは1案で決めず、最低3案は比較する。

## フック作成チェックリスト

- [ ] 続きを見る理由がある／頭に「？」が残る／答えを全部言っていない
- [ ] 一瞬で理解できる（専門用語・弱い固有名詞がない）
- [ ] 広すぎず狭すぎない（ターゲットに刺さっている）
- [ ] 映像が浮かぶ／映像・テロップ・アフレコが重複せず一致している
- [ ] 無駄な言葉を削った／抽象的すぎず具体的すぎない
- [ ] 煽りすぎていない／ブランドを傷つけない／使い古された表現ではない
- [ ] 3案以上比較した／なぜ強いか説明できる

## instagram-pdca での使い方

- **ワークフロー1（分析）**でフックの強さを評価する際、上記4軸＋守り・鮮度で判定する
- **ワークフロー2（Plan）**で下書き作成前、既存台本スキルが生成したフック（または `pattern-library.md` の型の一言目）をこのフレームワークで3案評価し、最も強い1案を選ぶ
- 型自体の追加・改変は行わない（本ファイルは評価基準の追加であり、`pattern-library.md` の型定義とは役割が異なる）
