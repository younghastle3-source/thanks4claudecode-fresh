### 区間抽出ヘルパ（**コードフェンス対応版。旧版は使用禁止**）

```bash
SEC()      { awk -v h="$2" '/^`{3}/{fence=!fence; if(f)print; next} fence{if(f)print;next} $0 ~ h {f=1;next} /^## /{f=0} f' "$1"; }
NF_()      { awk '/^`{3}/{fence=!fence;next} !fence'; }
FB_()      { awk '/^`{3}/{fence=!fence;next} fence'; }
H2C()      { awk '/^`{3}/{fence=!fence;next} !fence && /^## /{c++} END{print c+0}' "$1"; }
CANONBLK() { awk -v a="$2" -v b="$3" '$0 ~ a{f=1} f{print} f && $0 ~ b{exit}' "$1"; }
```

- `SEC` は見出し区間を切り出す。**フェンス内の行も区間の一部として出力する**
  （プロンプト本体はフェンス内にあるため、これがないと DW6 / DW9 が検出できない）。
- `NF_` は標準入力からフェンス**内**の行を落とす。実体行のカウントに使う
  （プロンプト本体の11行を「実体行」として数えないため）。
- `FB_` は逆に、標準入力からフェンス**内**の行だけを取り出す。指示文の逐語照合に使う。
- `H2C` はフェンス内の `## ` を数えない H2 カウンタ。**`grep -c '^## '` は使わない**
  （state.md の known_issues `playbook_section_extraction_needs_fence_awareness` 参照。
  本タスクは新規にフェンスを2組増やすため、この事故が現実に起こり得る）。
- `CANONBLK` は正典から**開始行の正規表現 a 〜 終了行の正規表現 b** で囲まれたブロックを抜き出す。
  **行番号をハードコードしない**（正典は記事が追記されるたび行番号がずれるため。実際に
  91行 → 200行に増えている）。本 playbook で使うアンカーは I-9 に定義する。
- 終端は **`^## ` のみ**でよい（`#{1,2}` にすると将来フェンス外に `# ` コメントが来たとき区間が切れる）。
  このファイルの H1 は `# メイカラ マーケティングスキル` 1箇所だけで、新規5区間の直後には現れない。
- `SEC` は `### ` でも `---`（水平線）でも区間を閉じない。
  実体行のカウントは `^- ` / `^{数字}. ` / `^|` に限定すること（`---` を数えないため）。
- 前提: SKILL.md 中のコードフェンスは ` ``` ` のみで**開閉が釣り合っている**こと
  （base 574b9ad で12行＝6組、本タスクで4行＝2組を追加して**合計16行**。DW10 が固定値で検証する）。

- **`1ヶ月` は base 0件・`1か月` は base 2件**。本タスクの必須語は**カタカナの `1ヶ月`** である。
- **日本語・記号を含む固定文字列の照合は必ず `grep -qF` / `grep -cF` / `grep -qxF`**
  （正規表現メタ誤爆の防止）。
- **変数に入れた複数行テキストの再出力は必ず `printf '%s\n' "$VAR"`**。
  `echo "$VAR"` は zsh でエスケープの扱いが bash と食い違い得る。
- **Markdown 表の行を数えるときに `grep -E` を使わない**。`|` は ERE の選択演算子なので
  `grep -cE '^|'` は「空文字列にマッチ」＝常に真になり、検査が黙って無効化される。
  表の行数は必ず `grep -c '^|'`（**-E なし**）で数える。
  **これは表の行数カウントに限った禁止であり、`grep -E` 一般の禁止ではない。**
  `grep -cE '担当者|社員|部下'` のように `|` を選択演算子として**意図的に**使う許可語/競合語リストや、
  `grep -qE '1人目(は|を|に)社長'` のような肯定条件は正しい用法である
  （p_final.9 / ft4 の allowlist も `|` を意図的に使っている）。
- **一時ファイルは必ず `mktemp` で作る**。`/tmp/kai_d1.txt` のような固定名は
  同じ test_command が並行実行されたときに互いの出力を壊す。
  作った一時ファイルは同じ test_command 内で必ず `rm -f` する。
- **`grep -vc` を空入力に対して実行しない**（空文字列が1行として数えられ偽 FAIL になる）。
  該当箇所は全て `if [ -z "$X" ]` でガードしている。
- **見出し文字列に半角スペースを含めない**。本 playbook で追加する H2 5本は全て半角スペースなしに設計済み。
  test_command 内では `set -- '見出し' 閾値 ...` の位置パラメータ方式で回し、`for H in ...` の
  単語分割に依存しない。
- **`git` のパスは常に `git -c core.quotepath=false`**（非 ASCII パスの8進エスケープ防止）。
- **python3 は必ず `python3 -X utf8` で、`-c` は1行で書く**。
  複数行の `-c` 文字列は `test_command: |` のインデントと衝突して IndentationError になる。
  フェンス除去は awk で前処理し、python へは**標準入力**で渡す。
  `-X utf8` を付けるのは、**標準入力のデコードがロケール依存だから**である
  （`LANG` が `C` / 未設定のシェルで日本語を読ませると `UnicodeDecodeError` で落ち、
  test_command が「FAIL でも PASS でもない」壊れ方をする）。
  ファイル側は `open(..., encoding="utf-8")` で明示済みだが、**stdin は明示できない**ので `-X utf8` が要る。
- **`diff <(...) <(...)`（プロセス置換）は bash / zsh の両方で動く**（実測済み）。
  指示文の逐語照合は行ごとの `grep -qxF` ではなく `diff` で行う
  （`grep -qxF` は**行の欠落・並べ替え・空行の増減を検出できない**）。

### R2. p1 / p2 が繰り返し FAIL するときの打ち切り基準

```yaml
FAIL の種類で切り分ける:
  A. 内容不足（`w:` / `d:` / `entity:` / `rows:` / `cond:`）:
     → 正典を読み直して書き足す。**何回やり直してもよい**（worker の作業品質の問題）
  B. 意味ガードの発火（`hitori` / `hitori_pos` / `hitori_rival` / `hours` / `inga` /
     `tanshuku` / `bunsho` / `unit` / `judge`）:
     → **まず「自分の書いた文が本当に記事の主張を反転していないか」を疑う。**
       反転していたなら書き直す（正しい FAIL）。
     → 記事の主張どおりに書いているのに FAIL するなら**過検出**である。
       **その場合は自力で文面をねじ曲げて通そうとしないこと。**
       FAIL した実際の行を貼って pm に報告し、ガードの修正可否を判断させる。
  C. 逐語コピペ検出（`FAILcopy:`）:
     → 検出された行を自分の言葉で書き直す。これは想定内であり、pm 自身もモック初稿で踏んでいる

打ち切り基準（これを超えたら人間に上げる）:
  - 同一 subtask が **3回連続** FAIL し、かつ 3回目の FAIL 理由が 1回目と同じ種類
  - B の過検出が **2つ以上の subtask** で同時に起きている（＝ガード設計そのものの疑い）
  - `notcanon` が **3回連続**（＝正典の指示文ブロックが想定と違う可能性。I-9 のアンカーを疑う）
  - 経過にかかわらず、**DW11(b) の行数上限950を超えないと全条件を満たせない**と判明した時点で即座に停止
    （＝水増しで通そうとしている兆候。閾値のほうを見直すべきなので pm に上げる）

打ち切ったときの引き継ぎ:
  - worktree は**撤去しない**（途中成果を残す）
  - FAIL した test_command の**出力そのもの**と、該当区間の当該行を報告する
```
